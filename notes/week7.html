8.1 Shortest Paths with Negative Weights (Bellman-Ford)

The Bellman-Ford algorithm was one of the first applications of the dynamic programming paradigm. Given a source vertex s, it returns the shortest distances from s to all other vertices — provided there are no negative-weight cycles reachable from s. If a reachable negative cycle exists, the algorithm detects and reports it.

Why Dijkstra's Algorithm Fails with Negative Weights

Dijkstra's algorithm relies on a greedy invariant: once a vertex is finalised (popped from the priority queue), its distance is correct and will never improve. This invariant breaks in the presence of negative-weight edges.

Counterexample

Consider the graph: s → a with weight 6, s → b with weight 3, a → b with weight −4.

Dijkstra finalises b with distance 3 (via s → b). But the true shortest path is s → a → b with total weight 6 + (−4) = 2. Dijkstra gave the wrong answer because it finalised b before exploring the negative-weight shortcut.

The root cause: Dijkstra assumes that no future edge can decrease the distance to an already-finalised vertex. Negative edges violate this assumption.

Undefined Shortest Paths — Negative Cycles

If a negative-weight cycle is reachable from s and a vertex t is reachable from that cycle, then the shortest path s ↝ t is undefined (effectively −∞). Given any path P, you can always construct a shorter path P' by traversing the negative cycle one more time.

Example: s can reach cycle a → b → c with total edge weight −6 (i.e., −2 + (−3) + (−1) = −6), and from this cycle vertex d is reachable. There is no well-defined shortest path from s to d.

The Bellman-Ford Algorithm

Key Idea: Optimality of Subpaths

A critical fact from Week 5 (used in many shortest-path proofs): if P is a shortest path s ↝ v and u is the second-to-last vertex on P, then the sub-path s ↝ u is also a shortest path. If a shorter path R to u existed, then R + (u,v) would be a shorter path to v than P — contradiction.

Core Observation

If no negative cycles are reachable from s, then for every reachable vertex t there exists a simple shortest path (no repeated vertices). Why?

  • A positive-weight cycle on any path can be removed to get a strictly shorter path.
  • A zero-weight cycle can be removed to get an equally short simple path.
  • Only a negative cycle could help, but we assumed none are reachable.

Since any simple path visits at most |V| vertices, it uses at most |V| − 1 edges. Therefore it suffices to look for shortest paths of at most |V| − 1 edges.

DP Recurrence

Let OPT[i, v] = the minimum weight of any s ↝ v path using at most i edges. The recurrence is:

Bellman-Ford Recurrence

OPT[0, s] = 0; OPT[0, v] = ∞ for all v ≠ s.

OPT[i, v] = min(OPT[i−1, v],   minu:(u,v)∈E(OPT[i−1, u] + w(u,v)))

In words: the shortest path to v with at most i edges either (a) already has at most i−1 edges, or (b) ends with some edge (u,v) where the sub-path to u uses at most i−1 edges.

We want OPT[|V|−1, v] for all vertices v.

Optimised (Space-Efficient) Pseudocode

In practice, a space-efficient version is implemented that collapses the 2D table to a single 1D array. The counter i simply controls how many full passes over all edges are made. In each pass, edges are "relaxed" in-place.

Algorithm 54 — Bellman-Ford (Optimised) Time: O(|V| × |E|)  |  Space: O(|V|) 
function BELLMAN_FORD(G = (V, E), s):
    dist[1..|V|] = ∞
    pred[1..|V|] = null
    dist[s] = 0

    for i = 1 to |V| - 1 do
        for each edge (u, v) in E do
            if dist[u] + w(u, v) < dist[v] then
                dist[v] = dist[u] + w(u, v)
                pred[v] = u

    return dist[1..|V|], pred[1..|V|]

Why |V| − 1 Iterations?

After k iterations of the outer loop, dist[v] is guaranteed to be ≤ the weight of the shortest path from s to v using at most k edges. Since the longest simple path has at most |V|−1 edges, after |V|−1 iterations all shortest paths are found.

Note: with the in-place update, dist[v] may actually be correct even sooner depending on edge ordering — but the guarantee only holds after |V|−1 passes in the worst case.

Correctness (Induction Sketch)

Theorem — Correctness of Bellman-Ford

After at most |V|−1 iterations, Bellman-Ford terminates with correct distance estimates for all vertices whose shortest path is well-defined.

Proof sketch (induction on number of edges in shortest path):

  • Base case: dist[s] = 0 is correct (0-edge path to self).
  • Inductive step: Suppose all shortest paths of ≤ k edges are correct after k iterations. A shortest path to v with k+1 edges ends with edge (u,v). By the substructure property, the sub-path to u has ≤ k edges and is correct. In the (k+1)-th iteration, the edge (u,v) is relaxed, updating dist[v] = dist[u] + w(u,v) = δ(s,v). □

Order Matters for Speed (Not Correctness)

If edges are relaxed in a "lucky" order that mimics the shortest path directions (e.g., s→b, b→d, d→c, c→a), the algorithm can converge in a single outer iteration. If relaxed in "reverse" order (e.g., c→a first when dist[c]=∞), all |V|−1 iterations may be needed. Correctness is guaranteed regardless; only speed differs.

Early Stop Optimisation

If a complete pass over all edges results in no relaxations, the algorithm can terminate early — shortest paths have already been found. This also proves there are no reachable negative cycles (saving the need for the detection pass below).

Detecting Negative Cycles

Detection Method

After |V|−1 iterations, run one additional (|V|-th) iteration. If any distance estimate can still be improved, a negative cycle reachable from s exists — because a valid shortest path would already be optimal after |V|−1 passes.

Propagating -∞ to All Affected Vertices

To mark all vertices affected by a negative cycle with −∞: run |V| additional iterations (not just one). Any vertex whose distance estimate is updated in these extra iterations is reachable from the negative cycle. Set those distances to −∞. After this post-processing, each entry in dist is:

  • ∞ — vertex unreachable from s
  • −∞ — vertex reachable via a negative cycle (no well-defined shortest path)
  • A finite value — the correct shortest distance

Warning: Do not try to reconstruct paths to vertices with distance −∞ — the pred array may contain cycles.

Detecting Negative Cycles Anywhere in the Graph

Standard Bellman-Ford only detects negative cycles reachable from the chosen source. To detect any negative cycle in the entire graph: add an auxiliary vertex r and add zero-weight edges from r to every other vertex. Run Bellman-Ford with r as the source — any negative cycle is now reachable from r.

Dijkstra vs. Bellman-Ford: Comparison

Algorithm Time Complexity Negative Weights? Negative Cycles? Use When
Dijkstra (binary heap) O((|V| + |E|) log |V|) No No Non-negative weights, dense or sparse graphs
Bellman-Ford O(|V| × |E|) Yes Detects (reachable) Negative weights present, or need to detect negative cycles
Complexity Breakdown

Bellman-Ford outer loop: |V|−1 iterations. Inner loop: |E| edge relaxations. Each relaxation: O(1). Total: O(|V| × |E|).

For a connected graph with |E| = |V|−1 (a tree), this is O(|V|2). For a dense graph with |E| = O(|V|2), this is O(|V|3).

An advanced variant called the Shortest Path Faster Algorithm (SPFA) maintains a queue of edges to relax, reducing the average-case complexity to O(|E|) for sparse graphs — but the worst case remains O(|V| × |E|).

8.2 The All-Pairs Shortest Path Problem

Problem Statement

Given a weighted directed graph G = (V, E), find the shortest path between every pair of vertices (u, v). The output is a |V| × |V| distance matrix.

The simplest approach is to run a single-source shortest path algorithm from every vertex as the source. Depending on the graph type, different algorithms are preferred:

Approach Sparse (|E| ≈ |V|) Dense (|E| ≈ |V|2) Handles Negative Weights?
Repeated BFS (unweighted) O(|V|2) O(|V|3) N/A (unweighted)
Repeated Dijkstra O(|V|2 log |V|) O(|V|3 log |V|) No
Repeated Bellman-Ford O(|V|3) O(|V|4) Yes
Johnson's Algorithm O(|V|2 log |V|) O(|V|3 log |V|) Yes
Floyd-Warshall O(|V|3) O(|V|3) Yes
Choosing an Algorithm
  • No negative weights, dense graph: Floyd-Warshall or repeated Dijkstra are equivalent — both O(|V|3).
  • No negative weights, sparse graph: Repeated Dijkstra wins (O(|V|2 log |V|)).
  • Negative weights, any graph: Floyd-Warshall is simple and O(|V|3) regardless of density. Johnson's is better for sparse graphs.
  • Negative weights, sparse graph: Johnson's algorithm (re-weighting + Dijkstra) achieves O(|V|2 log |V|).

8.2.1 Floyd-Warshall Algorithm

Floyd-Warshall (Robert Floyd, Turing Award 1978; Stephen Warshall) is an elegant all-pairs shortest path algorithm based on dynamic programming. It runs in O(|V|3) time for any graph without negative cycles and uses O(|V|2) space.

Key Insight — Intermediate Vertices

Number the vertices 1 to n. The algorithm iteratively expands the set of allowed intermediate vertices. After the k-th outer iteration:

dist[u][v] = length of the shortest path u ↝ v using only vertices from {1, 2, ..., k} as intermediates.

Subproblem and Recurrence

Let D(k)[i][j] denote the shortest path distance from vertex i to vertex j using only vertices from {1, ..., k} as intermediate nodes.

Floyd-Warshall Recurrence

Base case (k=0):

  • D(0)[i][i] = 0 for all i
  • D(0)[i][j] = w(i,j) if edge (i,j) exists
  • D(0)[i][j] = ∞ otherwise

Recurrence:

D(k)[i][j] = min( D(k-1)[i][j],   D(k-1)[i][k] + D(k-1)[k][j] )

Interpretation: The shortest path from i to j either (a) does not use vertex k as an intermediate — so it equals D(k-1)[i][j] — or (b) it does pass through k, in which case it decomposes into two sub-paths: i ↝ k and k ↝ j, both only using intermediates {1, ..., k-1}.

Key Correctness Detail

When the path goes through k, vertex k appears exactly once (assuming no negative cycles). If it appeared multiple times, it would form a cycle, which could be removed for a non-positive net benefit. So the decomposition into two sub-paths i ↝ k and k ↝ j — neither using k as an intermediate — is valid.

Space Savings — Why We Don't Need the Superscript

Notice that the update uses D(k-1)[i][k] and D(k-1)[k][j]. When we are updating the k-th outer iteration in-place, the values dist[i][k] and dist[k][j] are unchanged during the k-th iteration (since any path through k as an intermediate to reach k would need k itself, forming a cycle). So we can safely update dist[u][v] in-place without allocating a new matrix — this is why the algorithm already uses DP space savings implicitly.

Algorithm Pseudocode

Algorithm 55 — Floyd-Warshall Time: O(|V|3)  |  Space: O(|V|2) 
function FLOYD_WARSHALL(G = (V, E)):
    dist[1..|V|][1..|V|] = ∞
    dist[v][v] = 0               for all vertices v
    dist[u][v] = w(u, v)         for all edges (u, v) in E

    for k = 1 to |V| do
        for u = 1 to |V| do
            for v = 1 to |V| do
                dist[u][v] = min(dist[u][v], dist[u][k] + dist[k][v])

    return dist[1..|V|][1..|V|]

Path Reconstruction — Predecessor Matrix

To recover the actual shortest paths (not just distances), maintain a predecessor matrix pred[u][v] = the vertex before v on the shortest path from u to v. Update it alongside the distance matrix:

// During initialisation:
pred[u][v] = u    for all edges (u, v) in E
pred[v][v] = null (or v)
pred[u][v] = null for all non-edges

// During the main loop:
if dist[u][k] + dist[k][v] < dist[u][v] then
    dist[u][v] = dist[u][k] + dist[k][v]
    pred[u][v] = pred[k][v]    // The predecessor of v on path from u is
                               // the same as predecessor of v on path from k

// To reconstruct path from u to v:
function GET_PATH(u, v):
    if pred[u][v] == null: return null  // No path
    path = [v]
    while pred[u][v] != u:
        v = pred[u][v]
        path.prepend(v)
    path.prepend(u)
    return path

Detecting Negative Cycles in Floyd-Warshall

Negative Cycle Detection

After running Floyd-Warshall, check the main diagonal of the distance matrix. If dist[v][v] < 0 for any vertex v, then v lies on a negative-weight cycle.

This is a key advantage over Bellman-Ford: Floyd-Warshall detects any negative cycle in the graph, not just those reachable from a particular source.

If a negative diagonal entry is found, return an error — the shortest paths are not well-defined for vertices affected by the cycle.

Correctness of Floyd-Warshall (Invariant)

Invariant: At the start of iteration k of the outer loop, dist[u][v] contains the length of the shortest path u ↝ v using only intermediate vertices from {1, ..., k−1}.

  • Base (k=1): No intermediates allowed yet. dist[u][v] is initialised to direct edge weights, which is correct.
  • Inductive step: Assume the invariant holds for k. We consider adding vertex k to the pool. The shortest path through k decomposes at k (visited exactly once, since a repeated visit would imply a cycle), giving sub-paths u ↝ k and k ↝ v both using only intermediates {1,...,k−1}. By the inductive hypothesis, dist[u][k] and dist[k][v] are optimal, so the update is correct.

8.3 Transitive Closure

Definition — Transitive Closure

The transitive closure of a directed graph G = (V, E) is a new graph G' = (V, E') on the same vertex set such that there is a directed edge (u, v) ∈ E' if and only if there exists a directed path from u to v in G (including u = v).

In other words: can vertex u reach vertex v?

The transitive closure can be reduced to the all-pairs shortest path problem: there is a path from u to v if and only if dist[u][v] < ∞. However, we can do better in terms of constants by storing a Boolean matrix instead of distances.

Warshall's Algorithm — Boolean Floyd-Warshall

Warshall's algorithm is the Boolean analogue of Floyd-Warshall. Instead of tracking distances, it tracks reachability using a Boolean matrix connected[u][v].

Warshall's Recurrence

TC(k)[i][j] = TC(k-1)[i][j]   OR   (TC(k-1)[i][k] AND TC(k-1)[k][j])

Interpretation: vertex i can reach vertex j using intermediates {1,...,k} if either:

  • It could already do so without vertex k, or
  • It can reach k (using intermediates {1,...,k-1}) AND k can reach j (using intermediates {1,...,k-1}).
Algorithm 56 — Warshall's Transitive Closure Time: O(|V|3)  |  Space: O(|V|2) 
function TRANSITIVE_CLOSURE(G = (V, E)):
    connected[1..|V|][1..|V|] = false
    connected[v][v] = true         for all vertices v
    connected[u][v] = true         for all edges (u, v) in E

    for k = 1 to |V| do
        for u = 1 to |V| do
            for v = 1 to |V| do
                connected[u][v] = connected[u][v]
                                   OR (connected[u][k] AND connected[k][v])

    return connected[1..|V|][1..|V|]

Space Optimisation with Bitvectors

Each row of the connected matrix can be stored as a bitvector (bitset), where each bit represents reachability to one vertex. The AND and OR operations then become single bitwise instructions on machine words of width w.

  • Space: O(|V|2 / w) bits instead of O(|V|2) booleans
  • Time: O(|V|3 / w) with bitwise operations (not covered in detail in this unit)

Transitive Closure Example

Consider graph with vertices {a, b, c, d, e} and edges a→b, b→c, c→d, d→b, e→a.

After running Warshall's algorithm, the transitive closure contains edges:

  • e can reach: e, a, b, c, d (via chain e→a→b→c→d and the b-c-d cycle)
  • a can reach: a, b, c, d (via a→b and the b-c-d cycle)
  • b, c, d can all reach each other (they form a cycle)
  • No vertex can reach e or a (no back edges)

8.4 The Critical Path Problem

Problem Statement — Longest Path in a DAG

The critical path problem is the problem of finding the longest (maximum-weight) path in a Directed Acyclic Graph (DAG).

Project management context: Vertices represent task completions (or milestones), edges represent tasks with weights equal to their duration, and edges dictate prerequisites. The longest path gives the minimum project completion time — the bottleneck sequence of tasks that determines the project schedule.

Why DAG? Why Not General Graphs?

Longest path in a general graph is NP-hard (it generalises the Hamiltonian path problem). On a DAG however, it admits optimal substructure and can be solved efficiently in O(|V| + |E|).

Optimal substructure of longest paths in DAGs: If P is the longest path starting at u, and (u, v) is the first edge of P, then the rest of P (from v onwards) must be the longest path starting at v. If a longer path from v existed, we could combine it with (u,v) to get a longer path from u — contradiction.

Note: This property does NOT hold for general graphs because cycles could be exploited.

Dynamic Programming Formulation

DP Recurrence — Longest Path from u

Let longest[u] = the length of the longest path that starts at vertex u.

Base case: longest[v] = 0 for all vertices v with no outgoing edges (sinks).

Recurrence:

longest[u] = maxv ∈ adj[u] ( w(u, v) + longest[v] )

The longest path from u is the best first step: for each outgoing edge (u, v), we take that edge (cost w(u,v)) and then follow the longest path from v.

Dependency Order

To compute longest[u], we need longest[v] for all outgoing neighbours v of u — i.e., all descendants of u must be computed first. This means we must process vertices in reverse topological order (sinks first, source last).

Bottom-Up Algorithm (Iterative)

Algorithm 57 — Bottom-Up Longest Path in a DAG Time: O(|V| + |E|)  |  Space: O(|V|) 
function CRITICAL_PATH_BOTTOM_UP(G = (V, E)):
    longest[1..|V|] = 0
    order = REVERSE(TOPOLOGICAL_SORT(G))   // Sinks come first

    for each vertex u in order do
        for each edge (u, v) adjacent to u do
            longest[u] = max(longest[u], w(u, v) + longest[v])

    return longest[1..|V|]

Top-Down Algorithm (Recursive with Memoisation)

Algorithm 58 — Recursive Longest Path in a DAG (Top-Down DP) Time: O(|V| + |E|)  |  Space: O(|V|) 
// longest[1..|V|] = null (uninitialised, used as memoisation table)

function CRITICAL_PATH(u):
    if longest[u] != null then
        return longest[u]      // Already computed (memoised)

    longest[u] = 0
    for each edge (u, v) adjacent to u do
        longest[u] = max(longest[u], w(u, v) + CRITICAL_PATH(v))

    return longest[u]

// Call CRITICAL_PATH(source) or CRITICAL_PATH(u) for each source of interest

Connection to Topological Sort and DP

Deep Insight — DFS, Topological Order, and DP

The recursive solution to the critical path problem reveals a fundamental relationship between depth-first search, topological ordering, and dynamic programming:

  • Every DP algorithm has a subproblem dependency graph — a DAG where each subproblem is a vertex and each dependency is a directed edge.
  • Bottom-up DP must process subproblems in a valid topological order of this dependency DAG.
  • Top-down DP (with memoisation) does not need to know the topological order in advance, because the recursion itself performs a DFS on the dependency DAG, which implicitly produces a valid reverse topological order.

This is why top-down recursion works "automatically" without needing to pre-compute a topological order: the DFS discovers and resolves dependencies on the fly.

Practical implication: Many DP problems can be rephrased as shortest/longest path problems on DAGs. For example, the coin change problem from Chapter 7 is equivalent to finding the shortest path in a DAG where nodes are dollar amounts and edges connect amount V to V - c_i for each coin denomination c_i.

Why Longest Path Requires a DAG (Not a General Graph)

General Graphs: Longest Path is NP-Hard

On a general directed or undirected graph, the longest simple path (no repeated vertices) problem is NP-hard. The key obstruction is cycles: in a graph with a positive-weight cycle, you could traverse it repeatedly to make the path arbitrarily long. Even ignoring such cycles, determining the longest acyclic path requires examining exponentially many candidate paths in the worst case.

DAGs avoid this problem because they have no cycles by definition, so topological order provides a clean dependency structure for the DP.

Early and Late Times, Slack (CPM Context)

In the context of Critical Path Method (CPM) project scheduling, two additional quantities are computed for each activity/edge:

Concept Definition Computation
Earliest Start of task (u,v) The earliest time task (u,v) can begin = earliest completion time of vertex u = longest path from source to u
Latest Start of task (u,v) The latest time task (u,v) can begin without delaying the project = total project length − longest path from v to sink − w(u,v)
Float / Slack of task (u,v) How much the task can be delayed without affecting the overall project duration = Latest Start − Earliest Start
Critical Path The longest path from source to sink All tasks on this path have zero slack — they cannot be delayed at all
Critical Path = Zero-Slack Activities

Any activity with float = 0 lies on the critical path. Delaying any critical-path activity by even a single time unit delays the entire project. Project managers focus resources on critical-path activities to accelerate the project, since non-critical activities have slack and won't impact the deadline.

Summary of Complexity

Critical Path Complexity
  • Topological sort: O(|V| + |E|)
  • Bottom-up DP traversal: O(|V| + |E|)
  • Top-down recursive DP: O(|V| + |E|)
  • Total: O(|V| + |E|)

This is linear in the size of the graph — optimal since we must at minimum read all vertices and edges.

Key Takeaways
  • Dijkstra fails with negative weights because its greedy finalisation invariant breaks. Use Bellman-Ford instead.
  • Bellman-Ford relaxes all edges |V|−1 times. The i-th iteration guarantees correct distances for shortest paths with ≤i edges.
  • Floyd-Warshall solves all-pairs shortest paths in O(|V|3) by iteratively expanding the set of allowable intermediate vertices. It equals or beats all alternatives for dense graphs.
  • Negative cycle detection: Bellman-Ford — run one extra iteration and check if any distance updates; Floyd-Warshall — check diagonal entries of the final matrix for negative values.
  • Transitive closure (Warshall's algorithm) is a Boolean variant of Floyd-Warshall — replace min(+) with OR(AND).
  • Critical path = longest path in a DAG = O(|V|+|E|) DP using reverse topological order. Top-down recursion implicitly discovers topological order via DFS.
  • DP subproblem dependencies form a DAG — bottom-up DP requires a topological order; top-down DP discovers one automatically via DFS.
