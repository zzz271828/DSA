Intro The Greedy Paradigm

Definition — Greedy Algorithm

A greedy algorithm makes a locally optimal choice at each step and commits to it, hoping to reach a globally optimal solution. It never reconsiders past choices.

When Does Greedy Work?

Not every problem admits a greedy solution. Two key properties must hold:

  • Greedy choice property: A globally optimal solution can always be reached by making a locally optimal (greedy) choice. The choice made first is safe — it does not preclude finding the global optimum.
  • Optimal substructure: An optimal solution to the problem contains optimal solutions to its subproblems. This is also required for dynamic programming, but greedy algorithms additionally need the greedy choice property.

Greedy vs Dynamic Programming

PropertyGreedyDynamic Programming

Exchange Argument — Correctness Proof Technique

The standard way to prove a greedy algorithm correct is the exchange argument:

  1. Assume there exists an optimal solution OPT that differs from the greedy solution.
  2. Find the first place they differ. Show that you can swap the optimal choice for the greedy choice without making the solution worse.
  3. By repeated swaps, transform OPT into the greedy solution while not increasing cost, proving the greedy solution is also optimal.
Key Insight

Both Prim's and Kruskal's correctness proofs use a specific form of the exchange argument: they maintain an invariant that the current partial solution is a subset of some MST. When the greedy edge is not already in that MST, they construct a new MST that includes the greedy edge with equal or lesser weight — proving the greedy choice is safe.

6.1 Dijkstra's Algorithm

Problem — Single-Source Shortest Paths (SSSP)

Given a weighted directed (or undirected) graph G = (V, E) with non-negative edge weights and a source vertex s, find the shortest path distance from s to every other vertex.

Why BFS Doesn't Work for Weighted Graphs

Breadth-first search finds shortest paths in terms of number of edges. In an unweighted graph all edges have weight 1, so fewest edges = shortest distance. Once we introduce different weights, a path with more edges may be shorter overall. For example:

  • Path A: 1 edge of weight 100
  • Path B: 5 edges each of weight 1 — total weight 5

BFS picks Path A (fewer edges) but Path B is actually shorter. We need a priority queue that orders by cumulative weight, not hop count.

Edge Relaxation

All shortest-path algorithms maintain a distance estimate dist[v] for each vertex — the length of the shortest path found so far. The core operation is relaxation: if we find a path to v via u that is shorter than our current estimate, we update it.

Definition — Relaxation (Triangle Inequality Enforcement)

Relaxing an edge (u, v) means checking whether the path s → u → v is shorter than the current best known path to v, and updating if so.

Algorithm 37 — Edge Relaxation O(1)
function RELAX(e = (u, v)):
    if dist[v] > dist[u] + w(u, v) then
        dist[v] = dist[u] + w(u, v)
        pred[v] = u

The pred (predecessor) array stores each vertex's parent in the shortest-path tree. Once all distances are finalised, the actual shortest path to any vertex can be reconstructed by tracing back through pred.

Key Ideas Behind Dijkstra's Algorithm

Greedy Insight
  1. Non-negative weights imply monotone paths: Any sub-path of a shortest path is itself a shortest path. Adding more edges with non-negative weights can only increase total distance — never decrease it.
  2. Safe greedy extraction: Suppose we know the exact shortest distances to every vertex in some settled set S. Among all vertices not yet in S, the one with the minimum current estimate has its distance finalised — no other path can provide a shortcut because all remaining edges are non-negative.
  3. Visit in distance order: Dijkstra's therefore works like a weighted BFS, visiting vertices in order of their distance from the source, using a min-priority queue.

Algorithm: Standard Version

The classical description uses a priority queue pre-loaded with all vertices, supporting a decrease-key operation.

Algorithm 38 — Dijkstra's Algorithm (Standard) O((|V|+|E|) log |V|)
function DIJKSTRA(G = (V, E), s):
    dist[1..n] = ∞
    pred[1..n] = 0
    dist[s] = 0
    Q = priority_queue(V[1..n], key(v) = dist[v])   // min-heap over all vertices

    while Q is not empty do
        u = Q.pop_min()                              // extract closest unvisited vertex
        for each edge e = (u, v) that goes from u to a node still in Q do
            // Priority queue keys must be updated if relax improves a distance estimate!
            RELAX(e)

    return dist[1..n], pred[1..n]

Once a vertex u is popped from Q, its distance estimate is final and will never improve further. We only relax edges to vertices still in Q (unvisited vertices).

Algorithm: Improved Version (No Decrease-Key)

Most standard library priority queues do not support decrease-key. A common practical variant avoids it entirely:

  • Start with only the source in the queue.
  • When an edge is relaxed, push the target vertex again with its new (lower) distance as the key.
  • When popping, check if the popped key equals dist[u]. If not, it is stale — skip it.
Algorithm 39 — Dijkstra's Algorithm (Improved, No Decrease-Key) O(|E| log |V|)
function DIJKSTRA(G = (V, E), s):
    dist[1..n] = ∞
    pred[1..n] = 0
    dist[s] = 0
    Q = priority_queue()
    Q.push(s, key = 0)

    while Q is not empty do
        u, key = Q.pop_min()
        if dist[u] == key then              // skip stale (out-of-date) entries
            for each edge e = (u, v) adjacent to u do
                if dist[v] > dist[u] + w(u, v) then
                    dist[v] = dist[u] + w(u, v)
                    pred[v] = u
                    Q.push(v, key = dist[v])

    return dist[1..n], pred[1..n]

The queue may now hold up to |E| entries instead of |V|, but since log(|E|) = O(log|V|) for simple graphs, the asymptotic complexity is unchanged.

Correctness Proof

Theorem — Correctness of Dijkstra's Algorithm

Given a graph G = (V, E) with non-negative weights and source s, Dijkstra's algorithm correctly finds shortest-path distances to each vertex v ∈ V.

Proof by induction on the set S of vertices removed from Q:

  • Base case: The source s is removed first with dist[s] = 0, which is correct since there are no negative edges.
  • Inductive step: Assume dist[v] is correct for all v ∈ S. Let u be the next vertex removed. Suppose for contradiction there exists a shorter path P: s → … → u with length less than dist[u].
    • Let x be the furthest vertex along P that lies in S. By the inductive hypothesis, dist[x] is correct.
    • Let y be the next vertex on P after x.
    • Since all edge weights are non-negative, dist(s → y) ≤ dist(s → u) < dist[u].
    • Edge (x, y) was relaxed when x was popped, so dist[y] = dist(s → y) < dist[u].
    • If y ≠ u: Dijkstra's would have popped y before u since dist[y] < dist[u]. Contradiction.
    • If y = u: dist[y] < dist[u] = dist[y]. Contradiction.
Critical Dependency on Non-negative Weights

The proof breaks down with negative weights. If a negative edge exists, the sub-path s → y could have a larger weight than the full path s → y → … → u (because the negative edge later decreases the total). So dist[y] ≥ dist[u] would not be a contradiction, and Dijkstra's could extract u before finalising the true shortest path via y.

For graphs with negative weights, use the Bellman-Ford algorithm instead (O(|V||E|)).

Complexity Analysis

The total cost formula is: O(|E| · Tupdate + |V| · Tfind)

Every edge is relaxed exactly once (update operation), and every vertex is extracted from the queue exactly once (find operation).

Complexity Note

For a connected graph, |E| ≥ |V| - 1, so the |E| log|V| term dominates. The complexity simplifies to Θ(E log V) when using a binary heap. Note that O(log|E|) = O(log|V|) for simple graphs since |E| ≤ |V|², so the improved version (no decrease-key) has the same asymptotic complexity.

Practical Implementation Notes

  • The standard library version (Python's heapq, Java's PriorityQueue) does not support decrease-key. Use the lazy deletion approach (Algorithm 39) instead.
  • In the lazy version, the queue may contain multiple entries for the same vertex. When a stale entry is popped (key > dist[u]), simply skip it.
  • To reconstruct the shortest path to any vertex, trace back through the pred array until reaching the source.

6.2 Minimum Spanning Trees

Definition — Spanning Tree

A spanning tree of a connected undirected graph G = (V, E) is a subgraph T that contains all vertices V and a subset E' ⊂ E of edges such that T is a tree (connected and acyclic). Any spanning tree of a graph with |V| vertices has exactly |V| - 1 edges.

Definition — Minimum Spanning Tree (MST)

A minimum spanning tree of a weighted undirected graph is a spanning tree whose total edge weight is minimum over all possible spanning trees. Formally, we minimise:

w(T) = ∑(u,v) ∈ E(T) w(u,v)

There may be multiple MSTs with the same minimum weight if tie-breaking edge weights exist.

Properties of MSTs

Cut Property (Safe Edges)

Cut Property

Let S be any subset of vertices (a cut). Among all edges crossing the cut (with one endpoint in S and one in V ∖ S), the minimum weight crossing edge is safe to add to the MST — it is guaranteed to belong to some MST.

This is the property that Prim's algorithm exploits: the set S is the tree built so far, and Prim's always picks the lightest edge crossing from S to V ∖ S.

Cycle Property

Cycle Property

For any cycle C in the graph, the maximum weight edge of C does not belong to any MST (assuming all edge weights are distinct). More generally, the heaviest edge in any cycle can always be excluded.

This is the property that Kruskal's algorithm exploits: it only adds edges that do not create a cycle, effectively always avoiding the maximum edge in any cycle.

Exchange Argument (General MST Invariant)

Both Prim's and Kruskal's maintain the same invariant throughout execution:

MST Invariant

At every iteration, the current set of selected edges T is a subset of some minimum spanning tree of G.

The exchange argument shows that when the greedy edge e is not in the assumed MST M, we can swap it with the heaviest edge on the alternative path in M (the edge x). Since w(e) ≤ w(x) by the greedy choice, the new tree M' = M ∪ {e} ∖ {x} has w(M') ≤ w(M), and since M was already minimum, w(M') = w(M), so M' is also an MST containing e.

General MST Strategy

An edge e is called safe if T ∪ {e} is a subset of some MST. Both greedy algorithms follow this generic strategy:

Generic MST Algorithm
T = empty
while T has fewer than |V| - 1 edges:
    find an edge e that is safe (does not violate the MST invariant)
    T = T ∪ {e}
return T

6.2.1 Prim's Algorithm

Key Idea

Prim's algorithm grows the MST one vertex at a time, starting from an arbitrary root. At each step, it adds the lightest edge connecting the current tree T to a vertex not yet in T. This is analogous to Dijkstra's algorithm, with one crucial difference:

PropertyDijkstra'sPrim's
GoalShortest path tree from sourceMinimum spanning tree
Priority key for vertex vTotal distance from source: dist[u] + w(u,v)Just the edge weight: w(u,v)
dist[v] meaningShortest cumulative distance from sourceMinimum edge weight to connect v to tree
Prim's vs Dijkstra's — The One Difference

In Dijkstra's, when relaxing edge (u, v), the new candidate distance is dist[u] + w(u, v) (cumulative path length). In Prim's, the new candidate key is just w(u, v) (the edge weight alone). Everything else — the priority queue, the pred/parent array, the loop structure — is identical.

Algorithm

Algorithm 40 — Prim's Algorithm O(|E| log|V|)
function PRIM(G = (V, E), r):
    dist[1..n] = ∞
    parent[1..n] = null
    T = ({r}, empty)                          // MST starts with root only
    dist[r] = 0
    Q = priority_queue(V[1..n], key(v) = dist[v])   // min-heap over all vertices

    while Q is not empty do
        u = Q.pop_min()                       // closest vertex to tree
        T.add_vertex(u)
        T.add_edge(parent[u], u)              // add the connecting edge to MST

        for each edge e = (u, v) adjacent to u do
            if v not in T and dist[v] > w(u, v) then
                // Remember to update the key of v in the priority queue!
                dist[v] = w(u, v)             // NOTE: only edge weight, not cumulative!
                parent[v] = u

    return T

Correctness of Prim's Algorithm

Theorem — Invariant of Prim's Algorithm

In every iteration of Prim's algorithm, the current set of selected edges T is a subset of some minimum spanning tree of G.

Proof (induction on iterations):

  • Base case: T is empty, so it is trivially a subset of any MST.
  • Inductive step: Assume T is a subset of MST M. Let e = (u, v) be the lightest edge from a vertex u ∈ T to a vertex v ∉ T (Prim's choice).
    • Case 1: e ∈ M. Then T ∪ {e} ⊆ M, and the invariant holds.
    • Case 2: e ∉ M. Since M is a spanning tree, M contains a unique path from u to v. At least one edge x = (a, b) on this path has a ∈ T and b ∉ T (otherwise u and v would already be connected in T). Since Prim's picks the lightest edge from T to outside, w(e) ≤ w(x). Removing x and adding e gives a new spanning tree M' = M ∪ {e} ∖ {x} with w(M') = w(M) + w(e) - w(x) ≤ w(M). Since M is minimum, w(M') = w(M), so M' is also an MST, and T ∪ {e} ⊆ M'.
Corollary — Correctness of Prim's Algorithm

Prim's algorithm produces a minimum spanning tree. Proof: The algorithm never creates a cycle (each new edge connects to a fresh vertex). Since G is connected, all vertices are eventually added. When complete, T is a spanning tree and, by the invariant, is a subset of some MST. Since all spanning trees have exactly |V|-1 edges, T itself must be that MST.

Complexity of Prim's Algorithm

Complexity

Prim's algorithm has the same structure as Dijkstra's:

  • The while loop executes |V| times (one per vertex).
  • Each vertex extraction from the min-heap: O(log|V|).
  • Each edge is examined once: Θ(|E|) total edge operations.
  • Each priority-queue key update: O(log|V|).

Total: Θ(|E| log|V| + |V| log|V|) = Θ(|E| log|V|) for connected graphs (since |E| ≥ |V|-1).

6.2.2 Kruskal's Algorithm

Key Idea

While Prim's grows a single tree from a root, Kruskal's takes a completely different global view. It starts with a forest of |V| singleton trees and repeatedly merges the two cheapest disconnected components by adding the globally minimum weight edge that connects them.

Kruskal's Strategy
  1. Sort all edges in ascending order of weight.
  2. For each edge (u, v) in sorted order: if u and v belong to different connected components, add the edge to T and merge their components.
  3. Skip edges that would create a cycle (both endpoints already in the same component).
  4. Stop when T has |V| - 1 edges.

Algorithm

Algorithm 41 — Kruskal's Algorithm O(|E| log|E|) = O(|E| log|V|)
function KRUSKAL(G = (V, E)):
    sort(E, key((u,v)) = w(u,v))        // Sort edges in ascending order of weight

    forest = UnionFind.initialise(n)    // |V| singleton components
    T = (V, empty)                      // Result tree: all vertices, no edges

    for each edge (u, v) in E do
        if forest.FIND(u) != forest.FIND(v) then  // Different components?
            forest.UNION(u, v)                     // Merge components
            T.add_edge(u, v)                       // Add edge to MST

    return T

Union-Find Data Structure

Kruskal's needs to efficiently determine whether two vertices are in the same component (FIND) and merge two components (UNION). This is the Union-Find (Disjoint Sets) data structure.

Core Idea: Forest of Trees

Each component is stored as a tree. A parent[] array stores the parent of each node; roots are their own parents. The set representative (component ID) is the root of the tree.

  • FIND(u): Follow parent pointers from u until reaching a root. Return the root as the component representative. Time: O(tree height).
  • UNION(u, v): Find roots of u and v. If different, attach one root as a child of the other. Time: O(FIND).
Union-Find Operations
function FIND(u):
    while parent[u] != u do
        u = parent[u]
    return u

function UNION(u, v):
    root_u = FIND(u)
    root_v = FIND(v)
    if root_u != root_v then
        parent[root_u] = root_v      // Attach root_u under root_v

Union by Size (Optimisation)

To prevent trees from becoming pathologically deep (O(V) height), always attach the smaller tree under the larger tree's root. Roots store negative values representing the size of their component (e.g., a root with parent value -4 heads a component of size 4).

With union by size, the tree height is bounded by O(log V), so FIND and UNION both cost O(log V).

Path Compression (Further Optimisation)

During a FIND operation, flatten the path by making every visited node point directly to the root. This amortises future FIND calls to near-constant time. Combined with union by size, the amortised cost per operation is O(α(V)), where α is the inverse Ackermann function — effectively constant for all practical inputs (α(n) < 5 for any n representable with the matter in the universe).

Union-Find Implementation Note

For FIT2004, you need to understand union by size. Path compression is discussed in the notes but is not examinable. With union by size alone, the total cost of all UNION and FIND operations in Kruskal's is Θ(V log V + E log V) = Θ(E log V).

Correctness of Kruskal's Algorithm

Theorem — Invariant of Kruskal's Algorithm

In every iteration of Kruskal's algorithm, the current set of selected edges T is a subset of some minimum spanning tree of G.

Proof (identical structure to Prim's):

  • Base case: T is empty, trivially a subset of any MST.
  • Inductive step: Assume T ⊆ MST M. Let e = (u, v) be the lightest edge connecting two different components in T (Kruskal's choice).
    • Case 1: e ∈ M. Then T ∪ {e} ⊆ M and the invariant holds.
    • Case 2: e ∉ M. M contains a unique path from u to v. Since u and v are in different components of T, at least one edge x on this M-path is not in T. Removing x disconnects M; adding e reconnects it forming M' = M ∪ {e} ∖ {x}. Since Kruskal's picks the globally lightest cross-component edge, w(e) ≤ w(x), so w(M') ≤ w(M), meaning M' is also an MST and T ∪ {e} ⊆ M'.
Corollary — Correctness of Kruskal's Algorithm

Kruskal's algorithm produces a minimum spanning tree. Union-Find explicitly prevents cycles, and since G is connected, the algorithm will find a spanning tree. By the invariant, that spanning tree is a subset of some MST. Since all spanning trees have |V|-1 edges, it equals that MST.

Complexity of Kruskal's Algorithm

Complexity Breakdown
  • Sorting edges: Θ(|E| log|E|) = Θ(|E| log|V|) (since log|E| = O(log|V|²) = O(log|V|))
  • Union-Find initialisation: Θ(|V|)
  • For loop: |E| iterations, each with 2 FIND calls and at most 1 UNION.
  • With union by size: each FIND is O(log|V|); total UNION cost is Θ(|V| log|V|).
  • Total: Θ(|E| log|V| + |V| log|V|) = Θ(|E| log|V|)

When to Use Each

  • Prim's is preferred for dense graphs: With an array-based priority queue (O(1) update, O(|V|) extract-min), Prim's achieves O(|V|²) which is optimal for dense graphs where |E| = Θ(|V|²). Kruskal's always pays O(|E| log|E|) for sorting.
  • Kruskal's is often preferred for sparse graphs: The sorting step is cheap when |E| is small, and Union-Find is simple to implement. Kruskal's also has the advantage of being able to process edges in any streaming order — you can stop as soon as |V|-1 edges have been added.
  • In practice: Both algorithms are O(|E| log|V|) with a binary heap. Kruskal's is often simpler to implement correctly. The choice often comes down to which is easier to reason about for the specific problem.
Conceptual Contrast

Prim's thinks globally about which vertex to add next (who is closest to the current tree?). Kruskal's thinks globally about which edge to add next (which is the cheapest edge that doesn't form a cycle?). Both are greedy, both are correct, and both achieve the same asymptotic complexity — they represent two fundamentally different decompositions of the MST problem.

Key Formulas and Identities

  • Dijkstra relaxation: update dist[v] when dist[u] + w(u,v) < dist[v]
  • Prim key update: update dist[v] when w(u,v) < dist[v] (edge weight only, no accumulation)
  • log|E| = O(log|V|) for simple graphs (since |E| ≤ |V|²)
  • Any spanning tree on |V| vertices has exactly |V| - 1 edges
  • Dijkstra total cost: O(|E| · Tupdate + |V| · Textract-min)
  • Kruskal's Union-Find total cost (union by size): Θ(V log V) for all unions

Common Exam Pitfalls

Watch Out
  • Dijkstra with negative edges: Dijkstra's is incorrect on graphs with negative weights. The greedy argument requires that sub-paths of shortest paths are themselves shortest paths, which fails with negative weights.
  • Prim's key is not cumulative: Unlike Dijkstra's, Prim's stores only the edge weight w(u,v) in dist[v], not dist[u] + w(u,v). A common mistake is accumulating distances as in Dijkstra's.
  • Kruskal's cycle detection: An edge (u, v) creates a cycle if and only if FIND(u) == FIND(v) (both endpoints already in the same component). The condition is checked before adding the edge.
  • MST not unique: If multiple edges have the same weight, there may be multiple MSTs. Both Prim's and Kruskal's find a valid MST, not necessarily the same one.
  • Greedy correctness proof structure: For both MST algorithms, the proof has two cases: (1) the greedy edge is already in some MST — trivially safe; (2) it's not — construct an alternative MST by an exchange argument.
