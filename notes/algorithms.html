Sorting Algorithms

8 algorithms
Algorithm Core Idea BestAverageWorstSpace Notation Stable?Notes
Insertion Sort Build the sorted portion one element at a time by shifting larger elements right to make room. Ω(n) Θ(n²) O(n²) O(1) n = number of elements ✓ Yes Best case on nearly-sorted input. Used as base in hybrid sorts (Timsort).
Selection Sort Repeatedly scan the unsorted portion to find its minimum, then swap it into place. Ω(n²) Θ(n²) O(n²) O(1) n = number of elements ✗ No Exactly n−1 swaps — minimal write operations. Not adaptive.
Merge Sort Recursively split the array in half, sort each half independently, then merge the two sorted halves. Ω(n log n) Θ(n log n) O(n log n) O(n) n = number of elements ✓ Yes Optimal comparison sort. Preferred for linked lists and external sorting.
Heapsort Build a max-heap in O(n), then repeatedly extract the maximum by swapping root with last and sifting down. Ω(n log n) Θ(n log n) O(n log n) O(1) n = number of elements ✗ No In-place and worst-case O(n log n). Poor cache performance vs Quicksort.
Quicksort Partition around a pivot so all elements left < pivot ≤ right, then recurse on each side. Ω(n log n) Θ(n log n) O(n²) O(log n) n = number of elements ✗ No Expected O(n log n) with random pivot. DNF variant handles many duplicates well.
Counting Sort Count occurrences of each value, compute cumulative counts, then write elements to their correct positions. Ω(n + k) Θ(n + k) O(n + k) O(k) n = number of elements
k = value range (max − min + 1)		 ✓ Yes Breaks the Ω(n log n) comparison lower bound by using integer structure.
Radix Sort (LSD) Sort by each digit position from least to most significant, using a stable sort (e.g. counting sort) each pass. Ω(d·n) Θ(d·n) O(d·n) O(n + k) n = number of elements
d = number of digit positions
k = alphabet/base size		 ✓ Yes Requires stable sub-sort per digit. Works on strings and fixed-width integers.
Bucket Sort Distribute elements into equally-spaced buckets by value, sort each bucket individually, then concatenate. Ω(n + k) Θ(n + k) O(n²) O(n) n = number of elements
k = number of buckets		 ✓ Yes Average O(n) for uniformly distributed input. Degrades if elements cluster.

Divide & Conquer

4 algorithms
Algorithm Core Idea TimeSpace Notation RecurrenceNotes
Binary Search Halve the search space each step by comparing the target with the midpoint of the remaining range. O(log n) O(1) n = number of elements in sorted array T(n)=T(n/2)+O(1) Requires sorted array. Master Theorem Case 2 → Θ(log n).
Merge Sort Split in half, sort each half recursively, merge the two sorted halves in O(n). O(n log n) O(n) n = number of elements T(n)=2T(n/2)+O(n) Master Theorem Case 2. Optimal worst-case comparison sort.
Quickselect Partition around a pivot; only recurse into the side that contains the k-th element. O(n) avg O(log n) n = number of elements
k = target rank (1-indexed)		 T(n)=T(n/2)+O(n) avg Expected O(n) with random pivot; worst O(n²). Use MoM for guaranteed O(n).
Median of Medians Group elements into sets of 5, find each group's median, then recurse on those medians to find a guaranteed good pivot. O(n) worst O(n) n = number of elements T(n)≤T(⌈n/5⌉)+T(7n/10)+O(n) Guarantees pivot ≥ 30% and ≤ 70% of elements. Large constant; rarely used in practice.

Graph Traversal & Basics

6 algorithms
Algorithm Core Idea TimeSpace Notation RepresentationNotes
DFS Explore as deep as possible along one branch before backtracking to try other branches. O(V + E) O(V) V = number of vertices
E = number of edges		 Adjacency list Uses a stack (or recursion). Classifies edges: tree, back, forward, cross.
BFS Explore all neighbours at the current distance before moving to vertices one step further away. O(V + E) O(V) V = number of vertices
E = number of edges		 Adjacency list Uses a queue. Finds shortest paths in unweighted graphs.
Topological Sort (DFS) Run DFS and push each vertex onto a stack immediately after all its outgoing neighbours finish — reversing the stack gives the topological order. O(V + E) O(V) V = number of vertices
E = number of edges		 Adjacency list Only valid on DAGs. A back edge in DFS indicates a cycle (no valid ordering).
Kahn's Algorithm Start with vertices of in-degree 0, emit them in order, and decrement neighbours' in-degrees — adding newly zero-degree vertices to the queue. O(V + E) O(V) V = number of vertices
E = number of edges		 Adj list + in-degree array BFS-based. If output has fewer than V vertices, graph has a cycle.
Union-Find Represent each connected component as a rooted tree; merge components by linking one root to another, and flatten paths during lookup. O(α(n)) amortised O(n) n = number of elements
α(n) = inverse Ackermann (≤ 4 for all practical n)		 Parent array Path compression + union by rank gives near-O(1) per operation. Used in Kruskal's.
SCC — Kosaraju's First DFS on G records finish times; second DFS on the reversed graph GT in reverse-finish order discovers each SCC. O(V + E) O(V) V = number of vertices
E = number of edges		 Adj list + reversed graph Two full DFS passes. Each vertex belongs to exactly one SCC.

Greedy — Shortest Paths & MST

5 algorithms
Algorithm Core Idea TimeSpace Notation Structure UsedNotes
Dijkstra's Always settle (finalise) the unvisited vertex with the smallest current distance, then relax all its outgoing edges. O((V + E) log V) O(V) V = number of vertices
E = number of edges		 Min-heap / Priority Queue Non-negative edge weights only. Single-source. Greedy choice property holds because weights ≥ 0.
Prim's (MST) Grow the MST one vertex at a time by always adding the cheapest edge that connects the current tree to a new vertex. O((V + E) log V) O(V) V = number of vertices
E = number of edges		 Min-heap on edge weights Similar structure to Dijkstra's but key = edge weight to tree, not distance from source.
Kruskal's (MST) Sort all edges by weight and greedily add each edge if it does not form a cycle (checked via Union-Find). O(E log E) O(V) V = number of vertices
E = number of edges		 Sorted edges + Union-Find O(E log E) dominated by sorting. Works on disconnected graphs (gives MSF).
Activity Selection Sort intervals by finish time and always pick the next interval that starts after the last selected one ends. O(n log n) O(1) n = number of activities/intervals Sort by finish time Greedy choice: earliest finish leaves the most room for future activities.
Huffman Coding Repeatedly merge the two nodes with the lowest frequency into a new combined node until one tree remains. O(n log n) O(n) n = number of distinct symbols Min-heap on frequency Produces optimal prefix-free binary code. Greedy: lowest-frequency symbols get longest codes.

Dynamic Programming

12 algorithms
Algorithm Core Idea TimeSpace Notation DP ShapeNotes
Fibonacci (DP) Compute F(n) = F(n−1) + F(n−2) iteratively, keeping only the last two values to avoid recomputing overlapping subproblems. O(n) O(1) n = index of desired Fibonacci number 1D rolling Canonical intro to DP. Naïve recursion is O(2n) due to repeated subproblems.
0/1 Knapsack For each item in order, decide: skip it (take previous best) or take it (add its value + best for remaining capacity). O(nW) O(nW) n = number of items
W = knapsack capacity		 2D: items × capacity Pseudo-polynomial (W can be exponential in input size). NP-hard in general.
Unbounded Knapsack Like 0/1 knapsack but each item can be used any number of times; reuse the same row when computing. O(nW) O(W) n = number of item types
W = knapsack capacity		 1D: capacity (updated in-place) Generalises coin change. Space-optimised to O(W) by processing items in-place.
Edit Distance (Levenshtein) Build a table where each cell is the minimum insert/delete/replace operations to transform a prefix of s into a prefix of t. O(mn) O(mn) m = length of string s
n = length of string t		 2D: len(s) × len(t) Used in spell-check, DNA alignment, diff tools. Can reconstruct alignment via backtracking.
Longest Common Subsequence If current characters match, extend the LCS of both prefixes; otherwise take the best of skipping one character from either string. O(mn) O(mn) m = length of first string
n = length of second string		 2D: len(s) × len(t) Foundation for edit distance and Unix diff.
Matrix Chain Multiplication For each chain length, try every split point and pick the split that minimises the total multiplication cost. O(n³) O(n²) n = number of matrices in the chain 2D interval DP Interval DP pattern: solve all sub-chains of length 2, then 3, …, then n.
Coin Change (min coins) For each amount from 1 to target, try every coin denomination and take 1 + the best solution for the remainder. O(nW) O(W) n = number of coin denominations
W = target amount		 1D: amounts 0 … W Unbounded knapsack variant. Reconstruct solution by backtracking the decision table.
Bellman-Ford Relax all edges V−1 times; shortest paths with at most k edges are correct after k rounds, and a (V)th relaxation signals a negative cycle. O(VE) O(V) V = number of vertices
E = number of edges		 1D dist array, V−1 passes over E Handles negative edge weights. Detects negative cycles. DP over shortest-path length.
Floyd-Warshall For each possible intermediate vertex k, check whether routing any pair (i, j) through k gives a shorter path than the current best. O(V³) O(V²) V = number of vertices 2D dist matrix, V phases All-pairs shortest paths. Negative cycle detected if dist[v][v] < 0 after completion.
Critical Path Method Forward pass in topological order gives earliest start times; backward pass gives latest start times; zero-float tasks form the critical path. O(V + E) O(V) V = number of tasks (vertices)
E = number of dependencies (edges)		 1D on DAG topo order Longest path in a DAG. Float = LST − EST; tasks with float = 0 cannot be delayed.
Longest Increasing Subsequence Maintain the smallest tail element seen for each subsequence length; binary search determines where each new element extends or replaces. O(n log n) O(n) n = number of elements 1D patience-sort array Naïve DP is O(n²). Patience-sort trick reduces to O(n log n) via binary search.
Optimal Sequence Alignment Extend edit distance with a scoring function for matches, mismatches, and gaps — choose the alignment that maximises (or minimises) total score. O(mn) O(mn) m = length of first sequence
n = length of second sequence		 2D scoring matrix Generalises edit distance. Used in bioinformatics (Needleman-Wunsch, Smith-Waterman).

Network Flow

7 algorithms
Algorithm Core Idea TimeSpace Notation Path StrategyNotes
Ford-Fulkerson Repeatedly find any path from source to sink in the residual graph and push as much flow as the bottleneck edge allows. O(E · |f*|) O(V + E) E = number of edges
|f*| = value of maximum flow		 DFS (any path) May not terminate with irrational capacities. Terminates and is O(E|f*|) for integers.
Edmonds-Karp Ford-Fulkerson using BFS to always find the shortest (fewest-edge) augmenting path, guaranteeing polynomial termination. O(VE²) O(V + E) V = number of vertices
E = number of edges		 BFS (shortest path) At most O(VE) augmentations since each BFS path length is non-decreasing.
Bipartite Matching Model as max-flow with unit capacities: source to all left vertices, each left-right edge, all right vertices to sink — max-flow = max matching. O(E√V) O(V + E) V = total vertices (left + right)
E = number of possible matches		 BFS phases (Hopcroft-Karp) Hopcroft-Karp finds augmenting paths in BFS layers for O(E√V). Simpler: O(VE) via Ford-Fulkerson.
Min-Cut (Max-Flow Theorem) After max-flow terminates, BFS on the residual graph from the source — reachable vertices form one side of the min s-t cut. — — s = source, t = sink
V = vertices, E = edges		 Residual reachability (BFS) Max-flow value = min-cut capacity (Max-Flow Min-Cut Theorem). Cut edges are saturated.
Circulation with Lower Bounds Subtract lower bounds from capacities to get a standard flow network with super-source/sink; check feasibility by computing max-flow on the modified graph. O(VE²) O(V + E) V = vertices, E = edges
Lower bound l(e) ≤ capacity c(e)		 Reduction to max-flow Feasible circulation exists iff the modified max-flow saturates all edges from super-source.
Project Selection (Closure) Connect source to profitable projects and costly resources to sink; a min s-t cut separates "selected" from "rejected" optimally. O(VE²) O(V + E) V = projects + resources
E = dependency edges		 Reduction to min s-t cut Profit (selected) − min-cut value = optimal profit. Dependencies become infinite-capacity edges.
Survey Design Add per-customer and per-product capacity bounds as edges; whether a valid survey exists reduces to a feasible flow in the constructed network. O(VE²) O(V + E) V = customers + products
E = customer-product pairs		 Reduction to flow feasibility Lower/upper bounds on edges model "each customer answers at least/at most k questions".

Search Trees & Data Structures

8 structures
Structure Core Idea SearchInsertDeleteSpace Notation Notes
BST (unbalanced) Maintain the invariant: all keys in the left subtree < node key < all keys in right subtree, enabling O(h) lookup. O(h) O(h) O(h) O(n) n = number of stored keys
h = tree height (worst case h = n for sorted input)		 No balance guarantee: sorted insertion gives a linked list. Average h = O(log n) for random.
AVL Tree After every insert or delete, check the balance factor (height difference) at each ancestor and perform rotations to restore the ±1 invariant. O(log n) O(log n) O(log n) O(n) n = number of keys
h = O(log n) guaranteed		 Balance factor ∈ {−1, 0, 1} at every node. More rotations per op than Red-Black but shorter tree.
Red-Black Tree Colour nodes red or black and enforce five colour properties so no root-to-leaf path is more than twice any other, bounding height to 2 log n. O(log n) O(log n) O(log n) O(n) n = number of keys
h ≤ 2 log(n+1)		 At most 2 rotations per insert, 3 per delete. Used in Linux scheduler, Java TreeMap, C++ std::map.
2-3 Tree Allow each node to hold 1 or 2 keys (and 2 or 3 children); when a node overflows (3 keys), push the middle key up to the parent. O(log n) O(log n) O(log n) O(n) n = number of stored keys All leaves at the same depth — perfect height balance guaranteed. Conceptual precursor to B-trees.
B-Tree (order t) Generalise 2-3 trees to allow t−1 to 2t−1 keys per node, sizing nodes to fit one disk page to minimise I/O operations. O(log n) O(log n) O(log n) O(n) n = number of keys
t = minimum degree (t ≥ 2)		 Height ≤ logt(n). Disk-friendly: fewer seeks. Used in all major databases and file systems.
Binary Heap Store elements in an array with parent ≤ children (min-heap); restore the invariant after insert (rise/bubble-up) or delete (fall/sift-down). O(log n) O(log n) O(log n) O(n) n = number of elements
Build-heap: O(n) via bottom-up sift-down		 Build-heap O(n) (not O(n log n)). Extract-min O(log n). Basis for Dijkstra's, Prim's, Heapsort.
Hash Table Map each key to an array index via a hash function; resolve collisions by chaining (linked lists) or open addressing (probing). O(1) avg O(1) avg O(1) avg O(n) n = number of stored keys
α = load factor = n / table size		 Worst case O(n). Keep α < 0.75 for expected O(1). Universal hashing prevents adversarial worst cases.
Union-Find Represent each component as a rooted tree; flatten paths on every Find (path compression) and always attach shorter trees under taller ones (union by rank). O(α(n)) O(α(n)) — O(n) n = number of elements
α(n) = inverse Ackermann (≤ 4 always)		 With both optimisations: effectively O(1) per operation. Without: O(log n).

String Structures & Algorithms

6 algorithms
Structure / Algorithm Core Idea Build TimeSpaceQuery Time Notation Notes
Prefix Trie Store a set of strings as paths in a tree where every edge carries one character, sharing common prefixes. O(N · m) O(N · m) O(m) N = number of strings
m = length of string being queried		 Each character is one node. Supports prefix search, auto-complete. Space-heavy for large alphabets.
Patricia Trie (Compressed Trie) Collapse any chain of single-child nodes into a single edge labelled with the full substring, reducing node count to O(N). O(N · m) O(N) O(m) N = number of strings
m = query string length		 O(N) nodes for N strings regardless of their lengths. Edges store substrings, not single chars.
Suffix Trie Insert all n suffixes of a text into a trie so that any pattern can be found in O(pattern length) time by traversal from the root. O(m²) O(m²) O(p) m = text length
p = pattern length		 Uncompressed; O(m²) space makes it impractical for long texts. Conceptual basis for suffix trees.
Suffix Tree Compress the suffix trie by merging single-child chains; Ukkonen's algorithm builds this in O(m) time using implicit suffix links. O(m) O(m) O(p) m = text length
p = pattern length		 O(m) nodes. Supports LCS, LCP, all-occurrences queries. Edge labels stored as (start, end) index pairs.
Suffix Array Sort all suffix start indices lexicographically; pattern search is then a binary search over the sorted suffix order. O(m log m) O(m) O(p log m) m = text length
p = pattern length		 More cache-friendly than suffix tree. Can be built in O(m) with DC3/SA-IS; O(m log m) with radix sort.
KMP String Matching Pre-compute a failure function giving the longest proper prefix of the pattern that is also a suffix; on mismatch, jump back using this table instead of restarting. O(m) build O(m) O(n) search m = pattern length
n = text length		 Total O(n + m). Each character processed at most twice. Never goes backwards in text.

Master Theorem Quick Reference

CaseCore IdeaConditionSolutionExample
Case 1 The work done at the leaves dominates — there are polynomially more leaf nodes than work done at each level. f(n) = O(n^(log_b a − ε)), ε > 0 T(n) = Θ(n^(log_b a)) Strassen: a=7, b=2, f=Θ(n²), log₂7≈2.81 → Θ(n^2.81)
Case 2 Work per level is the same at every level of the recursion tree, so we pay that cost once per level (log n levels total). f(n) = Θ(n^(log_b a)) T(n) = Θ(n^(log_b a) · log n) Merge sort: a=2, b=2, f=Θ(n), log₂2=1 → Θ(n log n)
Case 3 The combine step at the root dominates — the per-level cost grows fast enough to dwarf the recursive sub-calls. f(n) = Ω(n^(log_b a + ε)) + regularity T(n) = Θ(f(n)) T(n)=2T(n/2)+n²: a=2,b=2,f=n²=Ω(n^(1+1)) → Θ(n²)

Asymptotic Notation

NotationCore IdeaFormal DefinitionMeaning
O(f(n)) The algorithm never does more work than c·f(n) for large enough n — this is the worst-case guarantee. ∃ c > 0, n₀: T(n) ≤ c·f(n) for all n ≥ n₀ Upper bound
Ω(f(n)) The algorithm always does at least c·f(n) work — used to state that no algorithm can do better than this. ∃ c > 0, n₀: T(n) ≥ c·f(n) for all n ≥ n₀ Lower bound
Θ(f(n)) The algorithm's cost is sandwiched between two constants times f(n) — both an upper and lower bound simultaneously. T(n) is both O(f(n)) and Ω(f(n)) Tight bound
o(f(n)) The algorithm's cost grows strictly slower than f(n) — the ratio T(n)/f(n) goes to zero. limn→∞ T(n)/f(n) = 0 Strict upper bound
ω(f(n)) The algorithm's cost grows strictly faster than f(n) — the ratio T(n)/f(n) goes to infinity. limn→∞ T(n)/f(n) = ∞ Strict lower bound
