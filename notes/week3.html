§3.2 Quicksort

Quicksort is a classic Divide-and-Conquer sorting algorithm invented by C.A.R. Hoare. Its key appeal is that it is in-place (with the right partition scheme), extremely cache-friendly in practice, and achieves average-case O(n log n) time — making it one of the fastest general-purpose sorting algorithms in real workloads.

Key Ideas – Quicksort
  1. Select some element of the array, called the pivot.
  2. Partition the array so that all items less than the pivot are to its left, all elements equal to the pivot are in the middle, and all elements greater than the pivot are to its right.
  3. Recursively Quicksort the left sub-array (elements less than pivot).
  4. Recursively Quicksort the right sub-array (elements greater than pivot).
Complexity Summary
CaseTimeAuxiliary Space
BestO(n log n)O(log n)
AverageO(n log n)O(log n)
WorstO(n²)O(log n)

Space assumes the tail-call optimisation (always recurse on the smaller half first). Without it, worst-case space is O(n). Quicksort is not stable when using in-place partition schemes.

The Partitioning Problem

The partitioning algorithm is the heart of Quicksort. Its choice determines whether Quicksort is in-place, stable, and how it handles duplicate elements. There are three main approaches covered in FIT2004:

  • Naive 3-way partition — simple, stable, but not in-place (uses O(n) extra space).
  • Hoare partition — in-place, efficient, but not stable and struggles with many duplicates.
  • Dutch National Flag (DNF) — in-place, handles duplicates optimally, not stable.

Naive 3-Way Partitioning (Out-of-place)

The simplest approach: scan the array and distribute each element into one of three temporary arrays — left (elements < pivot), pivots (elements = pivot), and right (elements > pivot). Then copy them back.

Stability Note
Elements that are equal to the pivot always end up in the pivots bucket in their original relative order, so naive 3-way partitioning is stable. However, it requires O(n) extra space, making the overall Quicksort non-in-place.
Algorithm 15 — Naive 3-Way Partition O(n) time · O(n) space 
function PARTITION(array[lo..hi], pivot):
    left   = empty array     // elements < pivot
    pivots = empty array     // elements = pivot
    right  = empty array     // elements > pivot

    for i = lo to hi do:
        if   array[i] < pivot  then  left.append(array[i])
        elif array[i] = pivot  then  pivots.append(array[i])
        else                         right.append(array[i])

    array[lo..hi] = left + pivots + right   // copy back (concatenation)
    return lo + length(left) + floor(length(pivots)/2)
                                            // return middle pivot position

Hoare Partition Algorithm (In-place)

Hoare's original scheme uses two pointers — one starting just after the pivot (at lo+1) and one at the far end (hi) — that march towards each other. The left pointer scans right looking for an element that is too large (i.e. > pivot), and the right pointer scans left looking for an element that is too small (i.e. ≤ pivot). When both bad elements are found, they are swapped. When the pointers cross, the pivot is swapped into its final sorted position at the right pointer.

Loop Invariant — Hoare Partition
At the start of each iteration:
  • array[lo] holds the pivot.
  • array[lo+1 .. i-1] ≤ pivot (left side — correctly placed).
  • array[j+1 .. hi] > pivot (right side — correctly placed).
  • array[i .. j] — unknown (not yet classified).
The invariant ensures that when i and j cross, the partition is complete.
Algorithm 16 — Hoare Partitioning O(n) time · O(1) space 
function PARTITION(array[lo..hi], array[p]):
    // array[p] is a reference to the pivot element
    swap(array[lo], array[p])      // move pivot to front

    i = lo + 1
    j = hi

    while i <= j do:
        while i <= j and array[i] <= array[lo] do:
            i = i + 1              // advance left ptr past "good" elements
        while i <= j and array[j] > array[lo] do:
            j = j - 1              // advance right ptr past "good" elements
        if i < j then:
            swap(array[i], array[j])
            i = i + 1
            j = j - 1

    swap(array[lo], array[j])      // pivot into final sorted position
    return j                       // pivot is now at index j

Properties of Hoare Partition
  • Pro: Each element is swapped at most once (pivot aside), very efficient in practice.
  • Pro: In-place — O(1) extra space.
  • Con: Not stable — elements equal to the pivot may be reordered.
  • Con: Tricky to implement correctly (off-by-one errors, termination conditions, edge cases).
  • Critical weakness: When many elements are equal to the pivot, all equal elements end up on the left side, leading to severely imbalanced partitions and O(n²) behaviour on arrays with many duplicates.

Dutch National Flag (DNF) Partition

Proposed by Edsger Dijkstra, the Dutch National Flag scheme partitions the array into three sections — < pivot, = pivot, > pivot — in-place in a single pass. After partitioning, only the two outer sections (< and >) need to be recursed on; the entire middle section (all elements equal to the pivot) is already in its final position.

DNF Problem Statement
Given an array of objects coloured red, white, or blue, arrange them so that all objects of the same colour are adjacent, in the order red → white → blue.

Mapping to Quicksort: red = elements < pivot, white = elements = pivot, blue = elements > pivot.
Loop Invariant — DNF Partition
Three pointers lo, mid, hi divide the array into four regions:
  • array[1 .. lo-1] — Red (elements < pivot)
  • array[lo .. mid-1] — White (elements = pivot)
  • array[mid .. hi] — Unknown (not yet classified)
  • array[hi+1 .. n] — Blue (elements > pivot)
Each iteration inspects array[mid] and shrinks the unknown region by one.

At each step we look at array[mid] and handle three cases:

  • Red (array[mid] < pivot): Swap with array[lo], increment both lo and mid. Red region grows, white region stays the same size (its left boundary shifts right).
  • White (array[mid] = pivot): Already in place. Just increment mid. White region grows.
  • Blue (array[mid] > pivot): Swap with array[hi], decrement hi. Blue region grows. Do not increment mid — the newly swapped element is still unknown.
Algorithm 17 — Dutch National Flag Partition O(n) time · O(1) space 
function PARTITION(array[1..n], pivot):
    lo  = 1
    mid = 1
    hi  = n

    while mid <= hi do:
        if array[mid] < pivot then:      // Red case
            swap(array[mid], array[lo])
            lo  += 1
            mid += 1
        elif array[mid] = pivot then:    // White case (already in place)
            mid += 1
        else:                            // Blue case (array[mid] > pivot)
            swap(array[mid], array[hi])
            hi -= 1
            // do NOT advance mid: re-examine the newly swapped element

    return lo, mid    // lo = start of white region, mid = start of blue region

Why DNF Is Critical
Without DNF (or an equivalent post-processing step), Quicksort degenerates to O(n²) on arrays with all identical elements. With DNF, all copies of the pivot value are placed in the middle in a single O(n) pass and are never touched again — turning a worst-case scenario into a trivial O(n) operation. In practice, three-way partitioning is essential for competitive Quicksort implementations.

Quicksort Algorithm

Using either Hoare or DNF partitioning, the top-level Quicksort is straightforward. The pivot is first placed in its final sorted position by the partition function, which returns the pivot's final index mid. Both sides are then sorted recursively.

Algorithm 18 — Quicksort Avg O(n log n) · Worst O(n²) 
function QUICKSORT(array[lo..hi]):
    if hi > lo then:
        pivot = array[lo]                  // choose first element as pivot
        mid   = PARTITION(array[lo..hi], pivot)
        QUICKSORT(array[lo .. mid-1])      // sort left (elements < pivot)
        QUICKSORT(array[mid+1 .. hi])      // sort right (elements > pivot)

// Initial call:
QUICKSORT(array, 1, len(array))

Space Optimisation — Tail-Call on the Larger Half
Quicksort is not technically in-place even with in-place partitioning, because the recursion stack uses O(log n)–O(n) space. To guarantee O(log n) stack space, always recurse on the smaller half first. Then either use tail-call optimisation or replace the second recursive call with a loop. This ensures the recursion depth is bounded by O(log n) regardless of pivot quality.

Complexity Analysis

Best Case — O(n log n)

The best case arises when every pivot chosen is the exact median of the remaining subarray, resulting in perfectly balanced partitions. The recursion tree has height log₂(n) and each level does O(n) total partitioning work, giving T(n) = 2T(n/2) + O(n) = O(n log n).

Worst Case — O(n²)

The worst case arises when the pivot is always the minimum or maximum element — for example, if we always pick the first element as pivot on an already-sorted array. Each partition splits the array into sizes 0 and n−1, giving O(n) levels of recursion.

Worst Case Trigger
Sorted or reverse-sorted input with a fixed pivot choice (e.g., always pick first element) causes O(n²) behaviour. The recurrence is:

T(n) = T(n-1) + T(0) + cn = T(n-1) + cn

Telescoping: T(n) = cn + c(n−1) + ... + c·1 = c·n(n+1)/2 = O(n²).

Average Case — O(n log n)

The average case is O(n log n). Two proofs are given in the course notes:

Coin-flip (intuitive) proof:

Define a "good pivot" as one in the middle 50% of the array (between the 25th and 75th percentile). A good pivot produces partitions of sizes at most 0.25n and 0.75n. The deepest branch of the recursion tree has length at most log4/3(n) = O(log n). Since half of all possible pivots are "good", we expect every second pivot to be good. The expected tree height is therefore 2·log4/3(n) = O(log n). Each level does O(n) work, so the average case is O(n log n).

Recurrence (rigorous) proof sketch:

If the k-th smallest element is selected as pivot, the recurrence is: 

E[T(n)] = n + 1 + (1/n) * sum_{k=1}^{n} (E[T(k-1)] + E[T(n-k)])
        = n + 1 + (2/n) * sum_{k=1}^{n} E[T(k-1)]

Using the substitution method (multiply by n, write the equation for n−1, subtract, and telescope), one arrives at: 

E[T(n)] / (n+1) = E[T(n-1)] / n + 2/(n+1)
               = sum_{k=1}^{n} 2/(k+1)   (telescoping)
               = O(log n)

Therefore  E[T(n)] = O(n log n).

Randomised Quicksort

The worst case is triggered by adversarial input when using a deterministic pivot rule (e.g., always pick the first element). The fix: select the pivot uniformly at random from the subarray before each partitioning step.

Theorem — Randomised Quicksort
With a uniformly random pivot, the expected time complexity of Quicksort is O(n log n) for any input — including sorted arrays.

Why does randomisation help? A deterministic adversary can no longer construct a bad input for a fixed pivot rule, because the pivot selection is unpredictable. The expected behaviour of randomised Quicksort matches the average-case analysis above — O(n log n) regardless of input order. In practice, a simple swap of a random element into the first position before partitioning is sufficient.

Practical Note
Randomised Quicksort is the algorithm of choice in most real-world implementations. Although the worst case is still theoretically O(n²), the probability of encountering it is astronomically small for large n. Introsort (used in C++ STL) combines Quicksort with Heapsort as a fallback to guarantee O(n log n) in the absolute worst case.

Ch. 4 Order Statistics and Selection

Definition — k-th Order Statistic
The k-th order statistic of a sequence of n elements is the k-th smallest element.
  • 1st order statistic = minimum.
  • n-th order statistic = maximum.
  • Median = the ⌊(n+1)/2⌋-th order statistic (or the average of the two middle elements for even n).
The Selection Problem
Given an unsorted sequence of n elements and a value k (1 ≤ k ≤ n), find the k-th smallest element without necessarily sorting the entire sequence.

Naive solution: Sort then index → O(n log n).
Goal: Can we do better — specifically O(n)?

4.1 Finding Minimums and Maximums

Finding just the minimum (or just the maximum) is straightforward in O(n) with a single linear scan, using exactly n − 1 comparisons. This is optimal: every comparison can only eliminate one element from consideration, so we need at least n − 1 comparisons to identify the minimum among n elements.

Algorithm 21 — Select Minimum O(n) · n-1 comparisons 
function SELECT_MIN(array[1..n]):
    min = array[1]
    for i = 2 to n do:
        if array[i] < min then:
            min = array[i]
    return min

Finding Both Min and Max Simultaneously

A naive adaptation of the above would find both min and max in 2n − 2 comparisons (two comparisons per element). However, we can do better using a pairwise strategy.

Theorem — Simultaneous Min-Max
Both the minimum and maximum of a sequence of n elements can be found using at most 3⌊n/2⌋ − 2 ≈ 1.5n comparisons, which is optimal (this is the lower bound).

The trick: Process elements in pairs. For each pair, first compare the two elements with each other (1 comparison), then compare the smaller with the current minimum (1 comparison) and the larger with the current maximum (1 comparison). This gives 3 comparisons per pair (3n/2 total) rather than 4 (2n total) — saving 25% of comparisons.

Algorithm 22 — Select Min and Max Simultaneously O(n) · ~1.5n comparisons 
function SELECT_MINMAX(array[1..n]):
    min = array[1]
    max = array[1]

    // start at index 2 if n is odd (already initialised with array[1])
    // start at index 1 if n is even (pair up all elements)
    for i = 1 + (n mod 2) to n, step 2 do:
        if array[i] < array[i+1] then:       // 1 comparison
            if array[i]   < min then min = array[i]      // 1 comparison
            if array[i+1] > max then max = array[i+1]    // 1 comparison
        else:
            if array[i]   > max then max = array[i]      // 1 comparison
            if array[i+1] < min then min = array[i+1]    // 1 comparison

    return min, max    // total: at most 3*(n/2) = 1.5n comparisons

4.2 The Quickselect Algorithm

For the general k-th order statistic, the key insight from Quicksort is that after partitioning, the pivot is in its final sorted position. If the pivot ends up at position mid, then:

  • If k = mid: the pivot is the k-th order statistic. Done.
  • If k < mid: the answer lies in the left sub-array. Discard the right.
  • If k > mid: the answer lies in the right sub-array. Discard the left.

This means we only ever recurse into one of the two sub-arrays — unlike Quicksort which recurses into both. In the best case this makes Quickselect O(n).

Algorithm 23 — Quickselect Avg O(n) · Worst O(n²) 
function QUICKSELECT(array[lo..hi], k):
    if hi > lo then:
        pivot = array[lo]                      // choose pivot (first element)
        mid   = PARTITION(array[lo..hi], pivot)

        if k < mid then:
            return QUICKSELECT(array[lo .. mid-1], k)   // answer in left half
        elif k > mid then:
            return QUICKSELECT(array[mid+1 .. hi], k)   // answer in right half
        else:
            return array[k]                    // pivot IS the k-th element
    else:
        return array[k]                        // base case: single element

4.3 Randomised Pivot Selection

By selecting the pivot uniformly at random, Quickselect achieves expected O(n) time. This is the simplest and empirically fastest strategy.

Theorem — Randomised Quickselect
Using randomised pivot selection, Quickselect has expected run time O(n).

Proof sketch (by induction):

Let T(n) denote the expected run time on an array of size n. Averaging over all possible pivot positions i (each equally likely with probability 1/n): 

E[T(n)] = (n+1) + (1/n) * [sum_{i=1}^{k-1} E[T(n-i)] + sum_{i=k+1}^{n} E[T(i-1)]]

Rearranging and bounding both sums by the larger half of terms:

E[T(n)] ≤ (n+1) + (2/n) * sum_{i=n/2}^{n-1} E[T(i)]

We claim E[T(n)] ≤ 4n. The base case T(1) = 2 ≤ 4 holds. For the inductive step, assuming E[T(i)] ≤ 4i for all i < n: 

E[T(n)] ≤ (n+1) + (2/n) * sum_{i=n/2}^{n-1} 4i
        ≤ (n+1) + (8/n) * [n(n-1)/2 - (n/2)(n/2-1)/2]
        ≤ (n+1) + (8/n) * (3n²/8)
        = (n+1) + 3n
        ≤ 4n + 1 ≈ 4n = C·n

Choosing C = 4 confirms E[T(n)] = O(n).

4.4 Median of Medians (Deterministic O(n) Selection)

While randomised Quickselect has excellent expected performance, it is not deterministic — there is always a (vanishingly small) chance of hitting the O(n²) worst case. The Median of Medians algorithm (Blum–Floyd–Pratt–Rivest–Tarjan, 1971) achieves guaranteed worst-case O(n) selection by choosing a provably "good enough" pivot deterministically.

The Key Insight
We do not need the exact median as a pivot. We only need a pivot that splits the array into two sub-arrays each of size at most a fixed fraction (e.g. 70%) of n. Any such pivot guarantees the recursion depth is O(log n), giving O(n) total work. Median of Medians finds a pivot guaranteed to lie between the 30th and 70th percentile.

The Algorithm — Step by Step

  1. Divide the n elements into ⌈n/5⌉ groups of at most 5 elements each.
  2. Find the median of each group using insertion sort (O(1) per group since groups have constant size 5). This produces ⌈n/5⌉ medians.
  3. Recursively find the median of those medians by calling Quickselect (with MoM pivot selection) on the list of ⌈n/5⌉ medians.
  4. Use the resulting "median of medians" as the pivot for the main partition step.
Algorithm 24 — Median of Medians O(n) worst case 
function MEDIAN_OF_MEDIANS(array[lo..hi]):
    if hi - lo < 5 then:
        return MEDIAN_OF_FIVE(array[lo..hi])     // base case: sort directly
    else:
        medians = empty array
        for i = lo to hi, step 5 do:
            j = min(i + 4, hi)
            median = MEDIAN_OF_FIVE(array[i..j]) // median of small group
            medians.append(median)
        n = length(medians)
        return QUICKSELECT(medians[1..n], floor((n+1)/2))
                                    // recursively find true median of medians
                                    // NOTE: this QUICKSELECT call must also
                                    // use MEDIAN_OF_MEDIANS for pivot selection!

function MEDIAN_OF_FIVE(array[lo..hi]):
    INSERTION_SORT(array[lo..hi])               // O(1) since at most 5 elements
    return array[(lo + hi) / 2]                 // return middle element

Mutual Recursion
MEDIAN_OF_MEDIANS calls QUICKSELECT, and QUICKSELECT calls MEDIAN_OF_MEDIANS to select its pivot. These functions are mutually recursive — they call back and forth on each other. This is what makes the analysis subtle.

Why the Pivot is "Good Enough" — The 30% Guarantee

Let m = median of medians (the pivot). Consider the ⌈n/5⌉ groups sorted by their medians:

  • By definition of median, at least half the group medians are ≤ m and at least half are ≥ m.
  • For each group whose median is ≤ m: within that group of 5, at least 3 elements (the median and the 2 below it) are ≤ m. So there are at least 3 × (n/10) = 3n/10 elements ≤ m.
  • Symmetrically, at least 3n/10 elements are ≥ m.

Therefore, after partitioning with m as pivot, both sub-arrays have size at most n − 3n/10 = 7n/10. The pivot is guaranteed to split at worst 70:30.

Theorem — Worst-Case O(n) Performance
Quickselect using the Median of Medians strategy has worst-case run time O(n).

Complexity Analysis — The Recurrence

Let T(n) be the time taken by Quickselect with the MoM pivot strategy. There are three contributions to the cost:

  • T(n/5): The recursive call inside MEDIAN_OF_MEDIANS to find the true median of the n/5 group medians.
  • T(7n/10): The main recursive call in Quickselect. The pivot guarantees at most 7n/10 elements on the larger side.
  • O(n): Linear work for the partition step plus finding the medians of all n/5 groups of 5.
Recurrence Relation
T(n) = T(n/5) + T(7n/10) + an   with T(0) = 0

Note: n/5 + 7n/10 = 2n/10 + 7n/10 = 9n/10 < n, so the subproblems together are strictly smaller than the original — a necessary condition for linear time.

Proof that T(n) = O(n) (by induction):

Choose a constant C ≥ 10a (where a is the linear-time constant in O(n) above). We prove T(n) ≤ Cn for all n.

Base case: T(0) = 0 ≤ C × 0. Holds trivially.

Inductive step: Assume T(n) ≤ Cn for all n < N. Then:

T(N) = aN + T(N/5) + T(7N/10)
     ≤ aN + C(N/5) + C(7N/10)    [inductive hypothesis]
     = aN + CN/5 + 7CN/10
     = aN + 9CN/10

Since C ≥ 10a  ⟹  a ≤ C/10  ⟹  aN ≤ CN/10

Therefore:
T(N) ≤ CN/10 + 9CN/10 = CN

By induction, T(n) ≤ Cn = O(n) for all n > 0. ∎
Why Groups of 5 Specifically?
  • Groups smaller than 5 (e.g. 3): the guarantee drops to <70:30 in the worst case, and T(n/3) + T(2n/3) with T(n/3) + T(2n/3) = n is not sufficient for O(n).
  • Groups of exactly 5 give the 70:30 split, and T(n/5) + T(7n/10) = 9n/10 < n — this is what makes the induction work.
  • Larger groups (e.g. 7) also work theoretically but increase the constant factor (finding medians of groups of 7 takes more work).
  • 5 is the smallest odd group size for which the algorithm is provably linear — a careful balance between the 30% guarantee and the constant factor overhead.

4.4 (cont.) Improving Quicksort with MoM

Armed with a deterministic O(n) selection algorithm, we can now make Quicksort worst-case O(n log n) — sometimes called Balanced Quicksort.

Before each partition step, call MEDIAN_OF_MEDIANS to find the true median and use it as the pivot. The pivot always splits the array at least 70:30, guaranteeing O(log n) recursion depth and O(n) work per level.

Theorem — Balanced Quicksort
Quicksort using Median of Medians pivot selection has worst-case O(n log n) time, matching Merge Sort and Heap Sort.

Updated Quickselect with MoM Pivot

Quickselect with Median-of-Medians Pivot O(n) worst case 
function QUICKSELECT(array[lo..hi], k):
    if lo >= hi then:
        return array[k]
    pivot = MEDIAN_OF_MEDIANS(array, lo, hi)   // guaranteed "good" pivot
    mid   = PARTITION(array[lo..hi], pivot)
    if k < mid then:
        return QUICKSELECT(array[lo .. mid-1], k)
    elif k > mid then:
        return QUICKSELECT(array[mid+1 .. hi], k)
    else:
        return array[k]
Practical Reality — The Anticlimax
Despite the beautiful theoretical guarantee, randomised Quicksort outperforms MoM-based Quicksort in practice. The MoM approach has large constant factors due to the overhead of finding medians of groups and the multiple passes over the data. In real systems, simple random pivot selection gives excellent empirical performance with negligible probability of hitting the worst case. MoM is primarily of theoretical importance — but it is profoundly satisfying to see a deterministic linear-time selection algorithm exist.
