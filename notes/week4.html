5.1 Modelling with Graphs

A graph is a way of encoding pairwise relationships among a set of objects. Each object is a vertex (or node) and a relationship between two objects is an edge (or arc). Graphs appear wherever data can be described as a network of connections.

Formal Definition
A graph G = (V, E) is defined by a set of vertices V and a set of edges E, where each edge e = (u, v) connects two vertices u and v. We write |V| (or n) for the number of vertices and |E| (or m) for the number of edges.

Graph Varieties

Direction

In an undirected graph, the edge (u, v) and (v, u) are the same — the relationship is symmetric (e.g. friendship). In a directed graph (digraph), the edge (u, v) is different from (v, u) — the relationship has a direction (e.g. a course prerequisite, a one-way street).

Weights

Edges may be unweighted (only presence/absence matters) or weighted, carrying a numerical value w(u, v) representing, for example, distance, cost, or bandwidth.

Simple Graphs vs. Multigraphs

  • A loop is an edge that connects a vertex to itself.
  • A multigraph allows multiple edges between the same pair of vertices.
  • A simple graph has no loops and no multiple edges between the same pair. Unless otherwise stated, assume simple graphs in this unit.

Key Terminology

Term Definition
Degree Number of edges incident to a vertex. For directed graphs: in-degree (incoming) and out-degree (outgoing).
Path A sequence of distinct, adjacent vertices. The length of a path is the number of edges (unweighted) or sum of edge weights (weighted).
Cycle A non-empty path that begins and ends at the same vertex, visiting no edge twice.
Connected An undirected graph is connected if every pair of vertices has a path between them.
Reachable Vertex v is reachable from u if there exists a path u → v.
Connected component A maximal connected subgraph. Any two vertices are either in the same component or in disjoint components.
Strongly connected (Directed graphs) Every vertex is mutually reachable from every other. Strongly connected components (SCCs) decompose a digraph.
Acyclic Contains no cycles.
Sparse / Dense A graph is sparse if |E| << |V|2 and dense if |E| ≈ |V|2.

Special Graph Types

Tree

Definition — Tree
An undirected graph G is a tree if it satisfies any (equivalently, all) of:
  • G is connected and acyclic.
  • G is connected and has exactly |V| − 1 edges.
  • G is acyclic and has exactly |V| − 1 edges.
  • G is acyclic, but adding any edge creates a cycle.
  • G is connected, but removing any single edge disconnects it.

Directed Acyclic Graph (DAG)

A DAG is a directed graph with no directed cycles. DAGs naturally model prerequisite or dependency relationships. The two key algorithmic problems on DAGs are topological sorting and the critical path problem.

Complete Graph

A complete graph Kn has an edge between every pair of vertices. It has |V|(|V|−1)/2 edges — the maximum possible for a simple undirected graph.

Bipartite Graph

A graph is bipartite if its vertices can be divided into two disjoint sets U and V such that every edge connects a vertex in U to a vertex in V. A graph is bipartite if and only if it contains no odd-length cycle. Bipartiteness can be tested in O(|V| + |E|) via BFS/DFS (two-colouring).

Real-World Modelling Examples

  • Road / transport networks: vertices = locations, edges = roads or routes, weights = distances or travel times. Problem: shortest path.
  • Social networks: vertices = people, undirected edges = friendship. Problem: connected components (friend groups), diameter (degrees of separation).
  • Course prerequisites: vertices = courses, directed edges = prerequisite relationships, forming a DAG. Problem: topological ordering (valid study plan), cycle detection (impossible degree).
  • Internet / communication networks: vertices = routers/ISPs, edges = connections. Problem: minimum spanning tree (cheapest connected infrastructure), shortest path (routing).
  • Information networks: vertices = webpages, directed edges = hyperlinks. Problem: PageRank, reachability.
Edge count bounds
  • Minimum edges in a connected undirected graph: |V| − 1 (a spanning tree)
  • Maximum edges in an undirected simple graph: |V|(|V|−1)/2 = O(|V|2)
  • Maximum edges in a directed simple graph: |V|(|V|−1) = O(|V|2)

5.2 Representation and Storage

The choice of graph representation has a direct impact on the time and space complexity of graph algorithms. The primary factor is the density of the graph.

Adjacency Matrix

An adjacency matrix for G = (V, E) is a |V| × |V| matrix A where:

  • For unweighted graphs: A[i][j] = 1 if edge (i, j) exists, else 0.
  • For weighted graphs: A[i][j] = w(i, j) if the edge exists, else 0 or ∞.
  • For undirected graphs, the matrix is symmetric: A[i][j] = A[j][i].
Complexity — Adjacency Matrix
  • Space: O(|V|2) — fixed regardless of |E|
  • Edge query (does edge (u,v) exist?): O(1)
  • Enumerate all neighbours of u: O(|V|) — must scan entire row
  • Best for: dense graphs (|E| ≈ |V|2), or when O(1) edge lookups are critical

Adjacency List

An adjacency list stores an array of size |V|, where entry i holds a list of all vertices adjacent to vertex i (along with edge weights for weighted graphs). Only existing edges are stored.

Complexity — Adjacency List
  • Space: O(|V| + |E|) — proportional to actual edges
  • Edge query (does edge (u,v) exist?): O(deg(u)), or O(log |V|) with a sorted list / BST
  • Enumerate all neighbours of u: O(deg(u)) — output-sensitive
  • Best for: sparse graphs (|E| << |V|2), most practical graph algorithms

Edge List

A flat list of all edges (u, v, w). Uses O(|E|) space. Cannot support fast adjacency queries or neighbour enumeration. Used primarily in Kruskal's MST algorithm, which needs edges sorted by weight.

Comparison Table

Property Adjacency Matrix Adjacency List Edge List
Space O(|V|2) O(|V| + |E|) O(|E|)
Edge query (u,v)? O(1) O(deg(u)) O(|E|)
Enumerate neighbours of u O(|V|) O(deg(u)) O(|E|)
Best for Dense graphs, fast lookups Sparse graphs, traversal Sorting edges (Kruskal's)
Practical Note
The vast majority of real-world graphs are sparse. Adjacency lists are the default choice for most graph algorithms (DFS, BFS, Dijkstra, Bellman-Ford, topological sort). Adjacency matrices shine when |V| is small and you need instant edge lookups, or when implementing Floyd-Warshall (all-pairs shortest paths).

5.3 Graph Traversal

Graph traversal algorithms systematically visit every vertex and edge in a graph. The two fundamental traversals — DFS and BFS — underpin an enormous range of graph algorithms. Both visit each vertex exactly once and work on directed and undirected graphs alike.

Depth-First Search (DFS)

DFS explores a graph by following a path as deep as possible from a starting vertex before backtracking. When a dead end is reached (no unvisited neighbours), the algorithm retreats to the most recent vertex that still has unvisited neighbours and continues from there.

Key Intuition
DFS is maze-solving by always taking the first unexplored corridor. When you hit a dead end, retrace your steps until you find an unexplored fork. The edges you actually traverse form a DFS tree.

Recursive DFS (canonical form)

Algorithm: Generic DFS (Recursive) O(|V| + |E|) 
function TRAVERSE(G = (V, E)):
    visited[1..n] = false
    for each vertex u = 1 to n:
        if not visited[u]:
            DFS(u)

function DFS(u):
    visited[u] = true
    for each vertex v adjacent to u:
        if not visited[v]:
            DFS(v)

Iterative DFS (explicit stack)

Algorithm: Iterative DFS O(|V| + |E|) 
function DFS_ITERATIVE(G = (V, E), s):
    visited[1..n] = false
    stack = Stack()
    stack.push(s)
    while stack is not empty:
        u = stack.pop()
        if not visited[u]:
            visited[u] = true
            for each vertex v adjacent to u:
                if not visited[v]:
                    stack.push(v)
Caveat
The iterative and recursive forms may visit neighbours in different orders depending on how the stack is populated. Both are valid DFS traversals but may produce different DFS trees.

Complexity Analysis

DFS Complexity
  • Time: O(|V| + |E|) — each vertex visited once, each edge examined at most twice (undirected) or once (directed).
  • Space: O(|V| + |E|) — for the graph representation plus O(|V|) recursion stack depth in the worst case.

DFS Tree and Edge Classification

The edges traversed by DFS (those that first discover a vertex) form a DFS tree (or DFS forest if the graph is disconnected). The remaining edges can be classified:

Edge TypeDescriptionSignificance
Tree edge Discovers a new (unvisited) vertex Forms the DFS tree
Back edge Leads to an ancestor in the DFS tree Indicates a cycle
Forward edge Leads to a descendant (directed graphs only) Skips levels of the DFS tree
Cross edge Leads to a vertex in a different subtree (directed graphs only) Connects different DFS branches
Theorem
In an undirected graph, DFS produces only tree edges and back edges. Forward and cross edges do not appear. Therefore, a back edge is equivalent to the presence of a cycle.

Finding Connected Components

A single DFS call from vertex u visits exactly the connected component containing u. By repeating DFS for each unvisited vertex, we discover all components in O(|V| + |E|).

Algorithm: Connected Components via DFS O(|V| + |E|) 
function CONNECTED_COMPONENTS(G = (V, E)):
    component[1..n] = null
    num_components = 0
    for each vertex u = 1 to n:
        if component[u] = null:
            num_components += 1
            DFS(u, num_components)
    return num_components, component[1..n]

function DFS(u, comp_num):
    component[u] = comp_num
    for each vertex v adjacent to u:
        if component[v] = null:
            DFS(v, comp_num)

Cycle Finding in Undirected Graphs

In an undirected graph, a back edge — an edge (u, v) where v is already visited and v is not the parent p of u — indicates a cycle. We must track the parent to avoid treating the edge we came from as a cycle.

Algorithm: Cycle Detection (Undirected Graph) O(|V| + |E|) 
function HAS_CYCLE(G = (V, E)):
    visited[1..n] = false
    for each vertex u = 1 to n:
        if not visited[u] and DFS(u, null) = true:
            return true
    return false

// Returns true if a cycle was detected starting from u with parent p
function DFS(u, p):
    visited[u] = true
    for each vertex v adjacent to u:
        if visited[v] and v != p:
            return true              // back edge found → cycle!
        else if v != p and DFS(v, u) = true:
            return true
    return false

Breadth-First Search (BFS)

BFS visits vertices in order of their distance from the source. It first visits all vertices 1 hop away, then all vertices 2 hops away, and so on. This layer-by-layer expansion is achieved using a queue (FIFO).

Key Intuition
BFS is like ripples spreading outward from a stone dropped in water — all vertices at distance k are reached before any vertex at distance k+1. The spanning tree produced by BFS is a shortest-path tree (for unweighted graphs).
Algorithm: Generic BFS O(|V| + |E|) 
function BFS(G = (V, E), s):
    visited[1..n] = false
    visited[s] = true
    queue = Queue()
    queue.push(s)
    while queue is not empty:
        u = queue.pop()                   // dequeue from front
        for each vertex v adjacent to u:
            if not visited[v]:
                visited[v] = true
                queue.push(v)             // enqueue at back

BFS Complexity
  • Time: O(|V| + |E|) — each vertex enqueued/dequeued once; each edge examined once (directed) or twice (undirected).
  • Space: O(|V| + |E|) for the graph plus O(|V|) for the queue and visited array.

BFS Tree

The edges via which BFS first discovers each vertex form a BFS tree (breadth-first tree). Crucially, the path from the source s to any vertex v in the BFS tree is a shortest path in the original unweighted graph — this is the key property that distinguishes BFS from DFS and motivates its use in shortest-path computations.

Applications Summary

  • Reachability: Is v reachable from u? Run DFS/BFS from u, check if v is visited.
  • Connected components: Repeated DFS/BFS (see Algorithm above).
  • Bipartiteness testing: BFS/DFS with 2-colouring; a graph is bipartite iff no two adjacent vertices share a colour.
  • Cycle detection: DFS back edges (undirected); for directed graphs, track "in-progress" nodes.
  • Shortest paths (unweighted): BFS, O(|V| + |E|). Covered in Section 5.4.
  • Topological sort: DFS reverse finish order, or Kahn's algorithm. Covered in Section 5.5.
  • Bridges & articulation points: DFS-based algorithms (advanced).

5.4 Shortest Paths

Shortest path problems ask: given a source vertex s, what is the minimum-weight path from s to each other vertex? This is one of the most practically important problems in graph theory (navigation, network routing, scheduling).

Properties of Shortest Paths

1. Optimal Substructure

Theorem — Optimal Substructure
Any subpath of a shortest path is itself a shortest path. If the shortest path from u to v passes through vertex x, then the subpath from u to x is a shortest path from u to x, and the subpath from x to v is a shortest path from x to v.

Proof sketch (contradiction): If a subpath were not shortest, replace it with a shorter one, making the whole path shorter — contradicting the assumption that the original was a shortest path.

2. Triangle Inequality

Theorem — Triangle Inequality
Let δ(s, v) denote the shortest-path distance from s to v. For any edge (u, v) with weight w(u, v):

δ(s, v) ≤ δ(s, u) + w(u, v)

In plain English: you cannot improve on a shortest path by adding an extra edge at the end. This underpins the relaxation step in Dijkstra's and Bellman-Ford algorithms.

3. Shortest Paths Are Simple (No Repeated Vertices)

We can always assume shortest paths are simple (no cycles):

  • A positive-weight cycle can be removed to shorten the path.
  • A zero-weight cycle can be removed without changing the path length.
  • A negative-weight cycle makes shortest paths undefined (can loop forever to decrease cost).

Therefore: a shortest path in a graph with n vertices uses at most |V| − 1 edges (a simple path through all vertices). This bound is exploited by the Bellman-Ford algorithm (Week 7).

Shortest Path Problem Variants

Single-Pair Shortest Path (SPSP)
Given G = (V, E) and vertices u, v ∈ V, find the shortest path from u to v.
Single-Source Shortest Path (SSSP)
Given G = (V, E) and a source s ∈ V, find the shortest path from s to every other vertex. Note: SSSP subsumes SPSP — once you have SSSP, you have the answer to any single-pair query.
All-Pairs Shortest Path (APSP)
Given G = (V, E), find shortest paths between every pair of vertices u, v ∈ V.

Unweighted SSSP via BFS

Because BFS visits vertices in order of distance from the source, it naturally computes shortest hop-counts (shortest paths in an unweighted graph). We augment standard BFS with two arrays:

  • dist[v]: the shortest distance (number of edges) from s to v.
  • pred[v]: the predecessor of v on the shortest path from s (used to reconstruct the path).
Algorithm: SSSP in Unweighted Graph (BFS) O(|V| + |E|) 
function BFS_SSSP(G = (V, E), s):
    dist[1..n] = ∞
    pred[1..n] = null
    queue = Queue()
    queue.push(s)
    dist[s] = 0
    while queue is not empty:
        u = queue.pop()
        for each vertex v adjacent to u:
            if dist[v] = ∞:              // v not yet visited
                dist[v] = dist[u] + 1
                pred[v] = u
                queue.push(v)

function GET_PATH(s, u, pred[1..n]):
    path = [u]
    while u != s:
        path.append(pred[u])
        u = pred[u]
    return reverse(path)

Why BFS gives shortest paths
BFS processes vertices strictly in non-decreasing order of distance from s. When a vertex v is first dequeued and its neighbour w is discovered, the distance assigned to w (dist[v] + 1) is optimal — because any shorter path to w would have caused w to be discovered earlier (contradiction with BFS ordering).

5.5 Topological Sorting

Definition — Topological Order
Given a DAG G = (V, E), a topological ordering is a permutation of the vertices such that for every directed edge (u, v), vertex u appears before vertex v in the permutation. Equivalently, if edges represent prerequisites, a topological order is a valid sequence for completing all tasks.

Key observations:

  • A topological ordering exists if and only if the graph is a DAG (no directed cycles).
  • A DAG can have multiple valid topological orderings (incomparable vertices can be in any relative order).
  • Both algorithms below run in O(|V| + |E|) and can detect cycles.

Applications

  • Course scheduling: compute a valid order to take subjects, respecting prerequisites.
  • Build systems: compile source files in the correct order (e.g. Makefile dependencies).
  • Project management: schedule tasks respecting "must-finish-before" constraints (critical path analysis).
  • Spreadsheet recalculation: update cells in the correct order based on formula dependencies.

Kahn's Algorithm

Kahn's algorithm maintains a count of in-degrees for each vertex. Vertices with in-degree 0 have no unresolved prerequisites and are ready to be output. As each vertex is processed, the in-degrees of its successors are decremented, potentially making more vertices ready.

Key Idea
A vertex can be placed next in the topological order when it has no remaining incoming edges (no outstanding prerequisites). Process these greedily using a queue.
Algorithm: Topological Sort — Kahn's Algorithm O(|V| + |E|) 
function TOPOLOGICAL_SORT_KAHN(G = (V, E)):
    // Compute in-degree for each vertex
    in_degree[1..n] = 0
    for each edge (u, v) in E:
        in_degree[v] += 1

    // Initialise queue with all zero-in-degree vertices
    order = empty array
    ready = Queue()
    for each vertex u = 1 to n:
        if in_degree[u] = 0:
            ready.push(u)

    while ready is not empty:
        u = ready.pop()
        order.append(u)
        for each edge (u, v) adjacent to u:
            in_degree[v] -= 1
            if in_degree[v] = 0:
                ready.push(v)

    // Cycle detection: if not all vertices are in order, a cycle exists
    if len(order) != n:
        return "Cycle detected — not a DAG"
    return order

Cycle Detection with Kahn's
If the graph contains a cycle, the vertices in the cycle will never have their in-degree reduced to 0 (because they depend on each other). After the algorithm finishes, len(order) < |V| signals a cycle.
Kahn's Algorithm Complexity
  • Time: O(|V| + |E|) — each vertex is enqueued/dequeued once; each edge is processed once.
  • Space: O(|V|) for in-degree array and queue.

DFS-Based Topological Sort

An alternative approach uses DFS. The key insight: after a DFS from vertex v finishes visiting all of v's descendants, v is appended to an output array. This guarantees that v's descendants all appear before v. Reversing the array gives the topological order.

Key Insight
In DFS, a vertex finishes (its DFS call returns) only after all vertices reachable from it have been visited. Therefore, the reverse of DFS finish order is a valid topological ordering.
Algorithm: Topological Sort — DFS-Based O(|V| + |E|) 
function TOPOLOGICAL_SORT_DFS(G = (V, E)):
    order = empty array
    visited[1..n] = false
    for each vertex v = 1 to n:
        if not visited[v]:
            DFS(v)
    return reverse(order)

function DFS(u):
    visited[u] = true
    for each vertex v adjacent to u:
        if not visited[v]:
            DFS(v)
    order.append(u)           // append AFTER visiting all descendants

5.6 Incremental Graph Connectivity (Union-Find)

The Problem

We have seen that DFS/BFS can find all connected components of a static graph in O(|V| + |E|). But what if the graph is changing — specifically, what if edges are being added one at a time, and we need to answer connectivity queries in between additions?

Definition — Incremental Connectivity Problem
Design a data structure supporting two operations efficiently:
  • CONNECTED(u, v): Are vertices u and v in the same connected component?
  • LINK(u, v): Add an edge between u and v (potentially merging two components).
Naively rerunning DFS/BFS after each LINK operation would cost O(|V| + |E|) per query. The union-find data structure solves this much more efficiently.

Union-Find / Disjoint-Set Data Structure

The union-find (or disjoint-set) data structure maintains a collection of n elements, each belonging to a disjoint set, supporting two operations:

  • FIND(u): Return the representative (root) of the set containing u.
  • UNION(u, v): Merge the sets containing u and v into one set.

Connectivity queries reduce to: are u and v connected? ⇔ FIND(u) = FIND(v).

Representation: Disjoint-Set Forest

Each set is represented as a rooted tree. Each node stores a pointer to its parent. The root of the tree is the representative. Roots point to themselves.

The FIND operation follows parent pointers up to the root. The UNION operation makes the root of one tree a child of the root of the other.

Naive Implementation (No Optimisations)

Algorithm: Union-Find — Naive O(n) per operation (worst case) 
function INITIALISE(n):
    parent[1..n] = [1, 2, 3, ..., n]   // each node is its own root

function FIND(x):
    if parent[x] = x:
        return x
    else:
        return FIND(parent[x])          // follow parent pointers to root

function UNION(x, y):
    parent[FIND(x)] = FIND(y)           // attach root of x's tree to root of y's tree

Problem with Naive Version
A sequence of UNION operations can create a long chain (degenerate tree), making subsequent FIND operations take O(n) time. Two optimisations fix this.

Optimisation 1: Path Compression

During a FIND, every node on the path to the root is made to point directly to the root. This flattens the tree so that future FIND operations on these nodes are O(1).

Effect
After path compression, subsequent FINDs on previously traversed nodes skip directly to the root, eliminating redundant traversal of long chains. Over a sequence of m operations, this gives a worst-case cost of O(m log n).
Algorithm: FIND with Path Compression Amortised O(log n) per operation 
function FIND(x):
    if parent[x] != x:
        parent[x] = FIND(parent[x])    // recursively compress; set parent to root
    return parent[x]

This elegant one-liner achieves path compression: after the recursive call returns the root, parent[x] is set directly to that root, flattening the path for future queries.

Optimisation 2: Union by Rank

Each tree is assigned a rank — an upper bound on its height. When merging two trees, always attach the tree with the smaller rank as a subtree of the one with the larger rank. This keeps trees balanced and short, preventing degenerate chains.

Effect
With union by rank, the height of any tree is at most O(log n). A sequence of m operations has worst-case cost O(m log n).
Algorithm: UNION by Rank Amortised O(log n) per operation 
function INITIALISE(n):
    parent[1..n] = [1, 2, ..., n]
    rank[1..n] = 0              // all trees start as single nodes with rank 0

function UNION(x, y):
    x = FIND(x)                 // get representatives
    y = FIND(y)
    if x = y: return            // already in the same set

    if rank[x] < rank[y]:
        parent[x] = y           // smaller rank tree becomes child of larger
    else:
        parent[y] = x           // y becomes child of x
        if rank[x] = rank[y]:
            rank[x] += 1        // only increase rank when merging equal-rank trees

Combined: Path Compression + Union by Rank

Theorem — Nearly O(1) Amortised Complexity
When both path compression and union by rank are used together, a sequence of m FIND and UNION operations on a universe of n elements has a total worst-case cost of:

O(m · α(n))

where α(n) is the inverse Ackermann function — an extraordinarily slowly growing function. For all practical values of n (up to the number of atoms in the universe), α(n) ≤ 4. This means each operation is effectively O(1) in practice.

This bound is provably optimal — no disjoint-set data structure can do better.

Complete Implementation (Both Optimisations)

Algorithm: Union-Find — Path Compression + Union by Rank O(α(n)) per operation 
function INITIALISE(n):
    parent[1..n] = [1, 2, ..., n]
    rank[1..n] = 0

function FIND(x):
    if parent[x] != x:
        parent[x] = FIND(parent[x])   // path compression
    return parent[x]

function UNION(x, y):
    x = FIND(x)
    y = FIND(y)
    if x = y: return                  // same component already

    if rank[x] < rank[y]:             // union by rank
        parent[x] = y
    else:
        parent[y] = x
        if rank[x] = rank[y]:
            rank[x] += 1

function CONNECTED(u, v):
    return FIND(u) = FIND(v)

function LINK(u, v):
    UNION(u, v)

Applications

  • Kruskal's Minimum Spanning Tree Algorithm (Week 5): Process edges in order of increasing weight; use UNION-FIND to check whether adding an edge would form a cycle (i.e. the two endpoints are already connected). If not, add the edge and call UNION.
  • Dynamic connectivity: In network monitoring, detect whether two nodes remain connected as new links are added (e.g. after a failure or upgrade).
  • Image processing: Connected-component labelling (flood fill) can use union-find to efficiently merge adjacent pixel regions.
  • Percolation theory: Determine when a random graph becomes connected as edges are added (e.g. modelling fluid flow through a porous medium).
Union-Find vs. DFS for Connectivity
For a static graph, DFS/BFS (O(|V| + |E|)) finds all components more efficiently than union-find. But for a dynamic graph with edge insertions, union-find (O(α(n)) per operation) vastly outperforms repeated DFS recomputation.
