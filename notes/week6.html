7.1 The Key Elements of Dynamic Programming

Dynamic programming (DP) solves a problem by breaking it into smaller subproblems and combining their solutions. Unlike divide-and-conquer, DP applies specifically when the same subproblem is needed multiple times — i.e., the subproblems overlap. The core insight is to compute each subproblem only once and store the result for later reuse.

Two Required Properties
  • Overlapping Subproblems: The same sub-computation is needed repeatedly (e.g., F(4) appears many times when computing F(6)).
  • Optimal Substructure: An optimal solution to the original problem can be constructed from optimal solutions to its subproblems.
DP vs Divide & Conquer
Both paradigms use optimal substructure. The difference: divide-and-conquer subproblems are independent (Mergesort), while DP subproblems overlap (Fibonacci). DP avoids recomputing overlapping subproblems via memoisation.

Motivating Example: Fibonacci Numbers

Fibonacci numbers are defined by the recurrence F(n) = F(n−1) + F(n−2), with base cases F(0) = 0, F(1) = 1.

Approach 1: Naive Recursion — O(2n)

The direct recursive implementation recomputes the same values exponentially many times. F(n−k) is computed F(k+1) times, so the leaves of the call tree explode. The recurrence T(n) = T(n−1) + T(n−2) + c has the same structure as Fibonacci itself, giving T(n) = O(F(n)) = O(φn) where φ ≈ 1.618 is the golden ratio.

Algorithm 42 — Naive Recursive Fibonacci Time: O(2n) | Space: O(n) stack 
function FIBONACCI(n):
    if n <= 1 then
        return n
    else
        return FIBONACCI(n-1) + FIBONACCI(n-2)

Approach 2: Memoised (Top-Down) — O(n)

Store each computed value in a memo table. On subsequent calls for the same n, return immediately from the table. Since each of the n subproblems is computed at most once, and each computation takes O(1) after the recursive calls, the total time is O(n).

Definition — Memoisation
Memoisation is the process of storing the results of previously computed subproblems so that they can be looked up in O(1) time instead of being recomputed.
Algorithm 43 — Memoised Fibonacci (Top-Down) Time: O(n) | Space: O(n) 
function FIBONACCI(n):
    memo[0..n] = null          // initialise memo table

    return FIBONACCI_MEMO(n)

function FIBONACCI_MEMO(n):
    if n <= 1 then return n    // base case
    if memo[n] = null then     // not yet computed
        memo[n] = FIBONACCI_MEMO(n-1) + FIBONACCI_MEMO(n-2)
    return memo[n]             // O(1) lookup on subsequent calls

Approach 3: Bottom-Up (Tabulation) — O(n)

Instead of top-down recursion, iteratively fill the table from the smallest subproblems upward. No recursion overhead; we simply compute fib[2], fib[3], ..., fib[n] in order.

Algorithm 44 — Bottom-Up Fibonacci Time: O(n) | Space: O(n) 
function FIBONACCI(n):
    fib[0..n] = 0
    fib[1] = 1
    for i = 2 to n do
        fib[i] = fib[i-1] + fib[i-2]
    return fib[n]

Optimal Substructure: The Coin Change Problem

Given denominations c1, c2, …, cn and a target value V, find the minimum number of coins that sum to exactly V.

Example: Coins = {1, 5, 6, 9}. Minimum coins for $13 = 3 (two $6 and one $1). Note that greedy fails here — greedily picking 9 then 1+1+1+1 gives 5 coins, not the optimal 3.

Identifying Subproblems

Define: MinCoins[v] = the fewest coins required to make exactly $v, for 0 ≤ v ≤ V.

This exhibits optimal substructure: if the optimal solution for $V uses a coin of value $x, then the remaining coins must be optimal for $(V − x).

Recurrence

Coin Change Recurrence
MinCoins[0]  = 0
MinCoins[v]  = infinity,            if v > 0 and v < c[i] for all i
MinCoins[v]  = min over all c[i] ≤ v of (1 + MinCoins[v - c[i]])

The base case MinCoins[0] = 0 terminates the recursion. The infinity case handles values that cannot be made (when no $1 coin exists).

Trace: Coins = {9, 6, 5, 1}, V = 12

MinCoins[12] = 1 + min(MinCoins[3], MinCoins[6], MinCoins[7], MinCoins[11]) = 1 + min(3, 1, 2, 2) = 2 (two $6 coins)

DP Strategy (from lectures)

  1. Assume you already know optimal solutions for all subproblems (smaller values).
  2. Observe how to build a solution to the current problem using those stored solutions (optimal substructure).
  3. Iteratively solve all subproblems from smallest to largest, memoising results.

How to Identify DP Problems

  • The problem asks for an optimal value (min/max/count) over a combinatorial space.
  • Brute force involves trying all possibilities (exponential).
  • You can identify a last choice that reduces the problem to smaller versions of itself.
  • Those smaller versions recur — the same sub-instance is needed from multiple parent problems.

7.2 Top-Down vs Bottom-Up Dynamic Programming

Both styles maintain a table of subproblem solutions. They differ in the order in which subproblems are solved and in their trade-offs.

Top-Down (Memoisation)

Write the natural recursive solution, then add a cache check at the start of the function. Subproblems are solved on demand — only those actually needed are ever computed. The recursion implicitly handles the dependency ordering.

Pros of Top-Down
  • No need to determine topological ordering of subproblems — recursion handles it automatically.
  • Only computes subproblems that are actually required (can save work if many subproblems are unreachable).
  • More intuitive for programmers comfortable with recursion.
Cons of Top-Down
  • Recursion overhead (function call stack). Each call has overhead versus a simple loop iteration.
  • Risk of stack overflow for very large inputs.
  • Cannot use the space-saving trick (see Section 7.8) because subproblem order is unknown.
Algorithm 45 — Top-Down Coin Change Time: O(nV) | Space: O(V) 
// memo[0..V] initialised to null; memo[0] = 0

function COIN_CHANGE_AUX(c[1..n], v):
    if v = 0 then return 0
    if memo[v] != null then return memo[v]   // already computed
    min_coins = infinity
    for i = 1 to n do
        if c[i] <= v then
            min_coins = min(min_coins, 1 + COIN_CHANGE_AUX(c, v - c[i]))
    memo[v] = min_coins
    return memo[v]

Bottom-Up (Tabulation)

Fill the DP table iteratively, starting from the base cases and working up to the full problem. The order of iteration must be a valid reverse topological order of the subproblem dependency graph — smaller problems before larger ones that depend on them.

Pros of Bottom-Up
  • No recursion overhead — iteration is faster in practice.
  • Enables clever optimisations like the space-saving trick.
  • Cache behavior is typically better (sequential memory access).
Cons of Bottom-Up
  • Must determine the correct iteration order (topological ordering of dependencies).
  • Computes all subproblems even if only a few are needed.
Algorithm 46 — Bottom-Up Coin Change Time: O(nV) | Space: O(V) 
function COIN_CHANGE(c[1..n], V):
    MinCoins[0..V] = infinity
    MinCoins[0] = 0                    // base case: 0 coins to make $0

    for v = 1 to V do
        for i = 1 to n do
            if c[i] <= v then
                MinCoins[v] = min(MinCoins[v], 1 + MinCoins[v - c[i]])

    return MinCoins[V]

7.3 Reconstructing Optimal Solutions

DP algorithms typically compute an optimal value (e.g., minimum coins = 3), but not the actual optimal solution (which coins). Two approaches exist to also reconstruct the solution.

Method 1: Backtracking Through the DP Table

After computing the full DP table, backtrack from the final answer by examining which choices could have led to the stored value. For coin change: start at MinCoins[V], find a coin ci such that MinCoins[V − ci] + 1 = MinCoins[V], take that coin, subtract from V, and repeat until V = 0.

Advantage: uses no extra memory (no second table). Slightly more computation during reconstruction (must search for valid coins).

Algorithm 47 — Coin Change Solution Reconstruction (Backtracking) Time: O(nV) | No extra space 
function GET_COINS(c[1..n], V, MinCoins[0..V]):
    if MinCoins[V] = infinity then return error
    coins = empty list

    while V > 0 do
        for i = 1 to n do
            if c[i] <= V and MinCoins[V] = 1 + MinCoins[V - c[i]] then
                coins.append(c[i])         // c[i] is part of optimal solution
                V = V - c[i]
                break                      // found one coin, continue loop
    return coins

Method 2: Decision Table

Maintain a second table OptCoin[0..V] alongside MinCoins[0..V]. Every time a new best is found for a subproblem, record which coin was chosen. Reconstruction then simply follows the decision table — O(V) time with no searching.

Advantage: reconstruction is faster and simpler. Disadvantage: O(V) extra memory for the decision table.

Algorithm 48 — Bottom-Up Coin Change with Decision Table Time: O(nV) | Space: O(V) extra 
function COIN_CHANGE(c[1..n], V):
    MinCoins[0..V] = infinity
    OptCoin[0..V] = null
    MinCoins[0] = 0

    for v = 1 to V do
        for i = 1 to n do
            if c[i] <= v then
                if 1 + MinCoins[v - c[i]] < MinCoins[v] then
                    MinCoins[v] = 1 + MinCoins[v - c[i]]
                    OptCoin[v] = c[i]      // record the optimal coin choice

    return MinCoins[V]

function GET_COINS(V, MinCoins, OptCoin):
    if MinCoins[V] = infinity then return error
    coins = empty list
    while V > 0 do
        coins.append(OptCoin[V])
        V = V - OptCoin[V]               // follow the decision table
    return coins

Backtracking for Edit Distance (from lectures)
For edit distance, backtracking proceeds from Dist[n][m] to Dist[0][0]:
  • If letters match and Dist[i][j] = Dist[i-1][j-1]: came from diagonal (no operation).
  • If Dist[i][j] = Dist[i-1][j-1] + 1: substitution (go diagonally).
  • If Dist[i][j] = Dist[i-1][j] + 1: deletion from S1 (go up).
  • If Dist[i][j] = Dist[i][j-1] + 1: insertion into S1 (go left).
Important Trade-off
The space-saving trick (Section 7.8) discards all but the most recent row of the DP table. This means backtracking is impossible if the space-saving trick is applied — you cannot reconstruct the solution without the full table.

7.4 The Unbounded Knapsack Problem

Problem Definition

Given n item types, each with a weight wi and value vi, and a backpack of capacity C kg, choose items (each type usable unlimited times) to maximise total value without exceeding capacity. There is no requirement to exactly fill the knapsack.

Example (from lecture): Items A(9kg,$550), B(5kg,$350), C(6kg,$180), D(1kg,$40), capacity = 12kg. Optimal = $780 (two B's and two D's: 10kg, $780).

Analogy to Coin Change
Unbounded knapsack is structurally identical to coin change: replace "coins" with "items", "amount" with "capacity", "minimum coins" with "maximum value", and "minimise" with "maximise". Both have a 1D DP table indexed by the capacity/amount.

Subproblem Definition

Define: MaxValue[c] = the maximum value achievable with capacity exactly c kg, for 0 ≤ c ≤ C.

Recurrence

Unbounded Knapsack Recurrence
MaxValue[0] = 0
MaxValue[c] = 0,                       if c < w[i] for all i
MaxValue[c] = max over all w[i] ≤ c of (v[i] + MaxValue[c - w[i]])

No "infeasible" case needed unlike coin change, since we do not require the knapsack to be completely full — any unused capacity simply contributes 0 value.

Implementation

Algorithm 49 — Bottom-Up Unbounded Knapsack Time: O(nC) | Space: O(C + n) 
function UNBOUNDED_KNAPSACK(v[1..n], w[1..n], C):
    MaxValue[0..C] = 0               // base: 0 value with 0 capacity

    for c = 1 to C do
        for i = 1 to n do
            if w[i] <= c then
                MaxValue[c] = max(MaxValue[c], v[i] + MaxValue[c - w[i]])

    return MaxValue[C]

            if thisValue > maxValue then

    Memo[Capacity] = maxValue
    return Memo[Capacity]

7.5 The 0-1 Knapsack Problem

Problem Definition

Same as unbounded knapsack, but each item may be taken at most once (0 or 1 of each). The naive approach of trying all 2n subsets is exponential. DP provides an O(nC) solution.

Example (from lecture): Items A(6kg,$230), B(1kg,$40), C(5kg,$350), D(9kg,$550), capacity = 11kg. Optimal = $590 (B+D = 10kg).

Why Unbounded's 1D Table Fails Here

In the unbounded case, picking an item reduces capacity but the item remains available. In 0-1, once item i is taken, it must be excluded from the subproblem. Tracking all subsets of used items requires 2n states — worse than brute force. The key observation: the order in which items are considered is irrelevant, so we can track only how many of the first i items have been considered.

2D Subproblem Definition

Define: MaxValue[i][c] = maximum value using items from the set {1, 2, …, i} with capacity c kg.

  • Base case: MaxValue[0][c] = 0 for all c (no items available).

Recurrence

0-1 Knapsack Recurrence
MaxValue[i][c] = 0,                              if i = 0
MaxValue[i][c] = MaxValue[i-1][c],              if w[i] > c   (item too heavy)
MaxValue[i][c] = max(
    MaxValue[i-1][c],                            // don't take item i
    v[i] + MaxValue[i-1][c - w[i]]              // take item i
)

The two choices for item i are: skip it (inherit the best from first i−1 items at capacity c), or take it (use item i's value plus optimal from first i−1 items at remaining capacity). We take the maximum of these two options.

Implementation

Algorithm 50 — Bottom-Up 0-1 Knapsack Time: O(nC) | Space: O(nC) 
function KNAPSACK(w[1..n], v[1..n], C):
    MaxValue[0..n][0..C] = 0          // base: 0 items = 0 value

    for i = 1 to n do
        for c = 1 to C do
            if w[i] <= c then
                MaxValue[i][c] = max(MaxValue[i-1][c],
                                     v[i] + MaxValue[i-1][c - w[i]])
            else
                MaxValue[i][c] = MaxValue[i-1][c]   // can't take item i

    return MaxValue[n][C]

Reconstruction: Backtracking the Table

Start at MaxValue[n][C]. For each row i from n down to 1:

  • If MaxValue[i][c] = MaxValue[i−1][c]: item i was not taken. Move to row i−1, same column.
  • Otherwise: item i was taken. Record item i, reduce c by w[i], move to row i−1.

Complexity and the Pseudo-Polynomial Note

Complexity
Time: O(nC) — n×C subproblems, each O(1) to compute.
Space: O(nC) — can be reduced to O(C) with space-saving trick (but reconstruction is then lost).

Important: O(nC) is pseudo-polynomial, not truly polynomial. C takes log2C bits to represent, so letting B = number of bits, C = 2B and the algorithm runs in O(n ⋅ 2B) — exponential in input size. The 0-1 knapsack is NP-complete.

7.6 The Edit Distance Problem

Problem Definition

Given two strings S1 and S2, find the minimum number of edit operations to transform S1 into S2. The permitted operations (each costing 1) are:

  1. Insert a character at any position.
  2. Delete a character from any position.
  3. Substitute (replace) one character with another.
Definition — Edit Distance (Levenshtein Distance)
The edit distance between strings S1 and S2 is the minimum number of single-character insert, delete, or substitute operations required to convert S1 into S2.

Applications: spell-checking and autocorrect, query suggestion in search engines, DNA/protein sequence alignment in bioinformatics.

Examples:

  • "computer" → "commuter": 1 substitution (p → m). Edit distance = 1.
  • "sport" → "sort": 1 deletion. Edit distance = 1.
  • "kitten" → "sitting": 2 substitutions + 1 insertion = edit distance 3.
  • "SINGS" → "SHINE": edit distance = 3 (replace S with E, delete G, insert H).

Identifying Optimal Subproblems

Consider aligning the last characters of the two strings. Three choices exist for the final column of the alignment:

  • Align S1[i] with S2[j]: cost 0 if equal, 1 if substitution.
  • Delete S1[i] (match S1[i] with a gap): cost 1, reduces to subproblem (i−1, j).
  • Insert S2[j] (match a gap with S2[j]): cost 1, reduces to subproblem (i, j−1).

Subproblem: Dist[i][j] = edit distance between the prefixes S1[1..i] and S2[1..j], for 0 ≤ i ≤ n, 0 ≤ j ≤ m.

Recurrence

Edit Distance Recurrence
Dist[0][j] = j          // empty S1: insert all j chars of S2
Dist[i][0] = i          // empty S2: delete all i chars of S1

If S1[i] = S2[j]:
    Dist[i][j] = Dist[i-1][j-1]          // characters match, no cost

Else:
    Dist[i][j] = 1 + min(
        Dist[i-1][j-1],   // substitute S1[i] for S2[j]
        Dist[i-1][j],     // delete S1[i]   (go up)
        Dist[i][j-1]      // insert S2[j]   (go left)
    )

Implementation

Algorithm 51 — Bottom-Up Edit Distance Time: O(nm) | Space: O(nm) 
function EDIT_DISTANCE(S1[1..n], S2[1..m]):
    Dist[0..n][0..m] = 0
    Dist[1..n][0] = 1, 2, ..., n     // base: delete S1 chars
    Dist[0][1..m] = 1, 2, ..., m     // base: insert S2 chars

    for i = 1 to n do
        for j = 1 to m do
            if S1[i] = S2[j] then
                Dist[i][j] = Dist[i-1][j-1]
            else
                Dist[i][j] = 1 + min(Dist[i-1][j-1], Dist[i-1][j], Dist[i][j-1])

    return Dist[n][m]

Optimal Sequence Alignment (Reconstruction)

Backtrack from Dist[n][m] to Dist[0][0]. At each cell [i][j]:

  • If S1[i] = S2[j] and Dist[i][j] = Dist[i−1][j−1]: match (no edit), move diagonally up-left.
  • If Dist[i][j] = Dist[i−1][j−1] + 1: substitution, move diagonally.
  • If Dist[i][j] = Dist[i−1][j] + 1: deletion from S1 (move up).
  • If Dist[i][j] = Dist[i][j−1] + 1: insertion into S1 (move left).

Build the alignment strings in reverse; reverse at the end.

Algorithm 52 — Optimal Sequence Alignment Time: O(n+m) after table is built 
function ALIGNMENT(S1[1..n], S2[1..m], Dist[0..n][0..m]):
    A1 = "", A2 = ""
    i = n, j = m

    while i + j > 0 do
        if i = 0 then
            A1 += "-", A2 += S2[j], j = j - 1
        else if j = 0 then
            A1 += S1[i], A2 += "-", i = i - 1
        else
            best = min(Dist[i-1][j-1], Dist[i][j-1], Dist[i-1][j])
            if S1[i] = S2[j] or Dist[i-1][j-1] = best then
                A1 += S1[i], A2 += S2[j]    // match or substitute
                i = i - 1, j = j - 1
            else if Dist[i-1][j] = best then
                A1 += S1[i], A2 += "-"      // delete from S1
                i = i - 1
            else
                A1 += "-", A2 += S2[j]      // insert into S1
                j = j - 1

    return reverse(A1), reverse(A2)

7.7 Matrix Chain Multiplication

Problem Definition

Given a sequence of matrices A1, A2, …, An with compatible dimensions, find the optimal parenthesisation that minimises the total number of scalar multiplications required to compute the product.

Multiplying an n×m matrix with an m×o matrix requires n×m×o scalar multiplications. Matrix multiplication is associative, so any parenthesisation gives the same result — but drastically different costs.

Example: A (4×2), B (2×5), C (5×3):

  • (A×B)×C: (4×2×5) + (4×5×3) = 40 + 60 = 100 multiplications
  • A×(B×C): (2×5×3) + (4×2×3) = 30 + 24 = 54 multiplications

The number of parenthesisations of n matrices is the (n−1)-th Catalan number, which grows exponentially — brute force is infeasible.

Identifying Optimal Subproblems

Consider the last multiplication performed. The product A1×…×An must be split at some point k: (A1×…×Ak)×(Ak+1×…×An). Both halves must also be multiplied optimally (optimal substructure).

Subproblem: DP[i][j] = minimum number of scalar multiplications to compute the product Ai×Ai+1×…×Aj, for 1 ≤ i ≤ j ≤ n.

Recurrence

Denote the dimensions as follows: matrix Ai has dimensions ci−1×ci (where c0 is the number of rows of A1 and ci is the number of columns of Ai).

When we split after matrix k, the two sub-results have dimensions ci−1×ck and ck×cj. Their final multiplication costs ci−1×ck×cj.

Matrix Multiplication Recurrence
DP[i][i] = 0                 // single matrix: no multiplication needed

DP[i][j] = min over all i ≤ k < j of:
    DP[i][k] + DP[k+1][j] + c[i-1] * c[k] * c[j]    // split at k

Bottom-Up Ordering

A key insight: we cannot simply iterate in row or column order. Each DP[i][j] depends on all DP[i][k] and DP[k+1][j] where i ≤ k < j — i.e., on subproblems involving shorter subsequences. We must iterate by increasing length of the subproblem (length = j−i+1).

Algorithm 53 — Optimal Matrix Chain Multiplication Time: O(n³) | Space: O(n²) 
function MATRIX_ORDER(c[0..n]):
    // c[i-1] = rows of A_i, c[i] = cols of A_i
    DP[1..n][1..n] = 0       // base: single matrix costs 0

    for length = 2 to n do                   // increasing subsequence length
        for i = 1 to n - length + 1 do
            j = i + length - 1
            best = infinity
            for k = i to j - 1 do           // try all split points
                cost = DP[i][k] + DP[k+1][j] + c[i-1] * c[k] * c[j]
                best = min(best, cost)
            DP[i][j] = best

    return DP[1][n]

There are O(n2) subproblems. For each subproblem DP[i][j] of length j−i, we try j−i split points. The total work over all subproblems is:

Complexity
Summing (j−i) over all valid (i,j) pairs = O(n3/6) = O(n3) time.
O(n2) subproblems → O(n2) space for the DP table.

To also reconstruct the optimal split, maintain a second n×n table storing the optimal k for each (i,j).

7.8 The Space-Saving Trick

Motivation

For edit distance and 0-1 knapsack, the DP table has O(nm) or O(nC) entries. For large inputs this is a lot of memory. However, inspecting the recurrences reveals that each row only ever looks at the immediately preceding row:

  • 0-1 Knapsack: Row i only uses row i−1.
  • Edit Distance: Row i only uses row i−1 (and the current row's left neighbor).

This means we only ever need two rows at a time.

The Rolling Array Technique

Instead of allocating a full 2D table, maintain just two 1D arrays: prev[] (the previous row) and curr[] (the current row being computed). After computing each row, swap them: prev becomes the old curr, and curr is reused for the next row.

Space-Optimised 0-1 Knapsack
function KNAPSACK_SPACE_OPTIMISED(w[1..n], v[1..n], C):
    prev[0..C] = 0         // row 0: no items
    for i = 1 to n do
        curr[0..C] = 0
        for c = 0 to C do
            if w[i] <= c then
                curr[c] = max(prev[c], v[i] + prev[c - w[i]])
            else
                curr[c] = prev[c]
        prev = curr        // discard old prev, current becomes new prev
    return prev[C]

The Critical Trade-Off

Trade-Off: Space vs Reconstruction
When using the space-saving trick, old rows are discarded. There is no way to backtrack through the table to reconstruct the actual optimal solution — only the optimal value can be recovered. If you need to output the actual items taken or the alignment sequence, you must keep the full table (or use a more advanced divide-and-conquer reconstruction technique).
Why Top-Down Cannot Use This Trick
The space-saving trick requires knowing the exact order in which rows are computed, so that the previous row can be discarded at the right time. In top-down DP, subproblems are solved in an order determined by the recursion — which is not known in advance — so it is impossible to safely discard earlier results.

General DP Problem-Solving Framework
  1. Identify subproblems: What smaller version of the problem needs to be solved? Define what the memo table stores.
  2. Write the recurrence: Assume all smaller subproblems are solved. Express the current answer in terms of those. Include all choices and take the best.
  3. Handle base cases: What is the answer for the smallest/trivial subproblems?
  4. Determine fill order: Bottom-up requires knowing which subproblems depend on which. Smaller before larger (or by length, row-by-row, etc.).
  5. Reconstruct if needed: Use a decision table or backtrack through the filled DP table.
  6. Optimise if needed: Apply space-saving trick if memory is a concern and reconstruction is not required.
