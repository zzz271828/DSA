Intro Flow Networks

A flow network is a model for routing material — whether physical (water in pipes, electricity in circuits, goods in logistics) or abstract (information, capacity) — from a single source to a single sink through a directed graph. The central question is: how much material can be pushed from source to sink without exceeding any edge's capacity?

Definition — Flow Network
A flow network is a connected directed graph G = (V, E) together with:
  • A source vertex s (only outgoing edges).
  • A sink vertex t (only incoming edges).
  • A non-negative integer capacity function c(u, v) ≥ 0 for every edge (u, v). If the edge does not exist, c(u, v) = 0.

What is a Flow?

A flow f is an assignment of a non-negative real number f(e) to each edge e that satisfies two properties:

Capacity Constraint
For every edge e:   0 ≤ f(e) ≤ c(e).
The flow on every edge must not exceed that edge's capacity.
Flow Conservation
For every vertex v ∈ V \ {s, t}:

∑ein ∈ Ein(v) f(ein) = ∑eout ∈ Eout(v) f(eout)

Every non-source, non-sink vertex must have equal total incoming and total outgoing flow — no material is created or destroyed at intermediate vertices.

Value of a Flow

The value of the flow |f| is defined as the total flow leaving the source:

|f| = Fout(s) = total flow out of s

Due to flow conservation, this is always equal to the total flow entering the sink. Intuitively, whatever is produced at the source must eventually arrive at the sink.

Key Insight — Flow of Every Cut is Equal
For any partition (S, T) of the vertices with s ∈ S and t ∈ T, the net flow crossing the cut — outgoing flow minus incoming flow — equals the total flow value |f|. This follows from flow conservation: since intermediate vertices are balanced, the only net production happens at s, and the only net consumption at t. This invariant is the backbone of the min-cut max-flow theorem.

The Maximum Flow Problem

Problem Statement — Maximum Flow
Given a flow network G = (V, E) with source s and sink t, find a flow f satisfying the capacity constraint and flow conservation such that |f| is maximised.

Real-World Applications

  • Routing water through pipe networks with capacity-limited pipes.
  • Electric current in circuits (Kirchhoff's current law is precisely flow conservation).
  • Optimising traffic flow on road networks to prevent bottlenecks.
  • Identifying critical vulnerabilities in power grids and supply chains.
  • Information routing in communication networks.
  • Solving a wide range of combinatorial problems (bipartite matching is one example).
Historical Note
The min-cut max-flow connection was first applied by the US Air Force in the Cold War era to identify minimal sets of rail links that, if destroyed, would cut off Soviet supply chains to Eastern Europe. Lester Ford Jr. and Delbert Fulkerson formalised the algorithm and theorem in 1956.

9.1 The Ford-Fulkerson Algorithm

The Ford-Fulkerson method is the foundational approach for solving the maximum flow problem. At its core, the idea is beautifully simple:

While more flow can be pushed through the network, push more flow through the network.

The challenge is figuring out where to push more flow — especially since naively filling paths to capacity can leave us stuck in a suboptimal solution. Consider a network where we greedily send flow along one path and saturate an edge that blocks a better routing: we need a mechanism to "undo" that decision and redirect flow elsewhere. This is the purpose of the residual network.

Pitfall — Greedy Path Filling is Not Enough
Simply finding any path from s to t with spare capacity and filling it to its bottleneck can yield a suboptimal result. Flow may need to be rerouted — reducing flow on one path to free up capacity for a better one. This is only possible via the residual network and backward edges.

High-Level Method

Algorithm 59 — Ford-Fulkerson Method (High Level) O(|E| × |f*|) with DFS 
function MAX_FLOW(G = (V, E), s, t):
    set initial flow f to 0 on all edges
    while there exists an augmenting path p in the residual network G_f do
        augment the flow f along path p as much as possible
    return f

The method is a skeleton — it describes what to do but not how to find augmenting paths. Different strategies for finding paths yield different time complexities. The two key operations are:

  1. Build and maintain the residual network as flow is augmented.
  2. Search for an augmenting path in the residual network (DFS, BFS, etc.).

9.1.1 The Residual Network

Given a flow network G = (V, E) and a current flow f, the residual network Gf captures exactly how much additional flow can be pushed through each edge, and also how much existing flow can be "undone" (redirected).

Definition — Residual Capacity
For each edge (u, v) in the original network with capacity c(u, v) and current flow f(u, v):
  • Forward residual edge (u → v): residual capacity cf(u, v) = c(u, v) − f(u, v)  — the remaining spare capacity in the forward direction.
  • Backward residual edge (v → u): residual capacity cf(v, u) = f(u, v)  — represents the ability to cancel (redirect) existing flow on (u, v).
Edges with residual capacity 0 can be omitted from the residual graph.

Why Backward Edges are Necessary

Without backward edges, Ford-Fulkerson can get stuck. Suppose we route 3 units along s → a → c → b → d → t and saturate c → b. No forward path to t exists anymore, yet the true maximum flow is higher. The backward edge b → c in the residual graph (with capacity 3) allows an augmenting path s → b → c → t to "steal" that 3 units of flow at c → b and redirect it via c → t instead — effectively rerouting without violating any constraint.

Implementation Trick — Unified Edge Representation
Rather than treating forward and backward edges differently in code, assign backward edges a capacity of 0 and maintain their flow as the negative of the corresponding forward edge's flow. The residual capacity formula cf(u, v) = c(u, v) − f(u, v) then works identically for both:
  • Forward edge: cf(u, v) = c(u, v) − f(u, v) (remaining capacity)
  • Backward edge: cf(v, u) = 0 − (−f(u, v)) = f(u, v) (flow that can be cancelled)
This eliminates duplicated code for handling the two edge types.

Handling Bidirectional Edges

If the original graph has edges in both directions between vertices x and y (say a/b capacity on x → y and c/d capacity on y → x), the residual network still has only 2 edges (not 4). The combined forward residual capacity from x to y is (b − a) + c: spare forward capacity plus reversible backward flow. This avoids double-counting.

9.1.2 Augmenting Paths

Definition — Augmenting Path
An augmenting path is any simple path (no repeated vertices) from source s to sink t in the residual network Gf using only edges with positive residual capacity.
Definition — Bottleneck Capacity
The bottleneck capacity of an augmenting path p is the minimum residual capacity over all edges on the path:

Δ(p) = min(u,v) ∈ p cf(u, v)

This is the maximum amount of additional flow that can be pushed along the path without violating any capacity constraint.

Augmenting Along a Path

Once an augmenting path with bottleneck Δ is found, we update the flow:

  • For each forward edge (u, v) on the path: f(u, v) += Δ (push more flow forward).
  • For each backward edge (v, u) on the path: f(u, v) -= Δ (cancel Δ units of existing flow on the corresponding forward edge, redirecting it).

After augmentation, the residual network must be updated: the forward residual capacity of edges on the path decreases by Δ, and the backward residual capacity increases by Δ.

Key Insight — Augmentation Always Increases Total Flow
When we augment along a backward edge, we are not "losing" flow — we are rerouting it. The flow reduced on the backward edge's forward counterpart gets replaced elsewhere by the augmenting path. Therefore every augmentation along a valid path strictly increases the total flow value by exactly Δ ≥ 1 (for integer capacities).

The Edge Saturation Concept

An edge is called saturated when its flow equals its capacity — no forward residual capacity remains. Ford-Fulkerson terminates when no augmenting path exists in the residual graph, which happens when every path from s to t passes through at least one saturated edge.

9.1.3 Implementation Using DFS

The simplest implementation of Ford-Fulkerson uses a depth-first search to find augmenting paths. The DFS simultaneously finds a path and augments along it, avoiding a second traversal. Each edge object stores its capacity, current flow, and a reverse pointer to its backward counterpart.

Algorithm 60 — Ford-Fulkerson with DFS O(|E| × |f*|) 
// DFS finds an augmenting path and augments along it simultaneously.
// Returns the bottleneck capacity of the path found, or 0 if none exists.
function DFS(u, t, bottleneck):
    if u == t then
        return bottleneck          // Reached sink — path complete

    visited[u] = true

    for each edge e = (u, v) adjacent to u do
        residual = e.capacity - e.flow
        if residual > 0 and not visited[v] then
            augment = DFS(v, t, min(bottleneck, residual))
            if augment > 0 then
                // Found a valid path — update flow along this edge
                e.flow        += augment
                e.reverse.flow -= augment   // Maintain backward edge
                return augment

    return 0   // No augmenting path found from u


function MAX_FLOW(G = (V, E), s, t):
    flow = 0
    do:
        visited[1..n] = false
        augment = DFS(s, t, infinity)
        flow += augment
    while augment > 0
    return flow

Key Implementation Notes

  • Back edges with capacity 0: Assigning backward edges capacity 0 and flow equal to the negative of the forward edge's flow unifies the residual formula cf(u, v) = c(u, v) − f(u, v) for both edge types.
  • Simultaneous augmentation: By augmenting during the DFS return phase (after the base case is reached), we avoid re-traversing the path separately.
  • Visited array reset each iteration: Each call to DFS starts fresh, ensuring the search is not confused by paths from previous iterations.
  • Reverse pointer: Each edge stores a direct reference to its reverse edge so updating e.reverse.flow is O(1).

Time Complexity

Complexity — Ford-Fulkerson with DFS
O(|E| × |f*|) where |f*| is the value of the maximum flow.

Breakdown:
  • Each DFS from s takes O(|E|) (connected graph, so |E| dominates |V|).
  • Each augmentation increases flow by at least 1 (integer capacities).
  • Therefore at most |f*| iterations of the main loop.
  • Total: O(|E| × |f*|).
Warning — Pseudo-Polynomial Complexity
O(|E| × |f*|) appears polynomial, but it is not polynomial in the input size. The value |f*| can be exponential in the number of bits needed to represent the capacities. For example, if all capacities are around C, then |f*| can be as large as |V| × C. With irrational capacities, Ford-Fulkerson may not even terminate.

Better Strategies: Edmonds-Karp and Others

AlgorithmPath SelectionTime ComplexityNotes
Ford-Fulkerson (DFS) Any augmenting path (DFS) O(|E| × |f*|) Simple, pseudo-polynomial; can loop with irrational capacities
Edmonds-Karp Shortest path (BFS — fewest edges) O(|V| × |E|²) Fully polynomial; guaranteed to terminate
Fattest Path Max-bottleneck path (modified Prim's) O(|E|² log|V| log(max c)) Better than Edmonds-Karp in some cases; harder to implement
Edmonds-Karp: BFS Gives Polynomial Guarantee
If we replace DFS with BFS (finding the shortest augmenting path by number of edges), the resulting Edmonds-Karp algorithm runs in O(|V| × |E|²) time — a true polynomial bound that is independent of flow values. The key insight is that BFS augmenting paths have monotonically non-decreasing lengths, bounding the number of augmentations.

9.2 The Minimum Cut Problem

The minimum cut problem asks: what is the cheapest set of edges to remove from a flow network in order to completely disconnect s from t? This has immediate practical interpretations — e.g., which roads to block to prevent a vehicle from reaching a destination, or which links to sever to isolate two parts of a network.

Definition — s-t Cut
An s-t cut C = (S, T) is a partition of the vertices V into two disjoint subsets S and T such that s ∈ S and t ∈ T.

The capacity of the cut is the total capacity of all edges going from S into T (outgoing edges of the cut):

c(S, T) = ∑u ∈ S, v ∈ T c(u, v)

Note: incoming edges of the cut (from T into S) are not subtracted from the capacity.
Definition — Minimum Cut
A minimum cut is an s-t cut C = (S, T) that minimises c(S, T) over all possible s-t cuts.

Flow of a Cut vs. Capacity of a Cut

For any s-t cut (S, T) and any flow f:

  • Flow of the cut = (total flow on outgoing edges from S to T) − (total flow on incoming edges from T to S).
  • The flow of the cut always equals the value |f| of the flow (proved via flow conservation — see insight below).
  • The flow of the cut is always ≤ the capacity of the cut, because f(e) ≤ c(e) for every edge, and incoming edges are not counted in capacity.
Proof Sketch — Flow of Every Cut Equals |f|
For any subset S containing s:

|f| = Fout(s) = Fout(s) + ∑v ∈ S\{s} (Fout(v) − Fin(v))

The added sum is zero by flow conservation. Expanding the sum, edges internal to S appear once as outgoing and once as incoming, cancelling out. What remains is exactly the net flow crossing from S into T. Therefore the flow of any cut = |f|.

Upper Bound: Flow ≤ Any Cut Capacity

Since flow of the network = flow of any cut ≤ capacity of that cut:

Maximum possible |f| ≤ capacity of the minimum cut

The stunning result of the min-cut max-flow theorem is that this upper bound is always achieved — maximum flow equals minimum cut capacity exactly.

9.2.1 The Min-Cut Max-Flow Theorem

Theorem — Min-Cut Max-Flow
Given a flow network G = (V, E) with source s and sink t, the value of the maximum s-t flow equals the capacity of the minimum s-t cut:

maxf |f| = min(S,T) c(S, T)

Proof Sketch

We need to show both directions:

Part 1 — Upper Bound: max flow ≤ min cut

For any flow f and any cut (S, T), the flow value |f| equals the net flow across the cut, which is at most the cut capacity (since each edge contributes at most its capacity, and incoming edges are not subtracted from the cut capacity). Therefore no flow can exceed any cut's capacity, and in particular, max |f| ≤ min c(S, T).

Part 2 — Achievability: there exists a flow and cut with equal values

Suppose Ford-Fulkerson has terminated — no augmenting path exists from s to t in the residual graph Gf. Define:

  • S = all vertices reachable from s in the residual graph.
  • T = all remaining vertices (including t, which is unreachable by assumption).

This is a valid s-t cut. We claim that the flow of the cut equals the capacity of the cut:

  • Every outgoing edge (u, v) with u ∈ S, v ∈ T is fully saturated: If f(u, v) < c(u, v), then the forward residual edge (u, v) would exist in Gf with positive capacity, making v reachable from s — contradicting v ∈ T.
  • Every incoming edge (v, u) with v ∈ T, u ∈ S carries zero flow: If f(v, u) > 0, then the backward residual edge (u, v) would exist in Gf, making v reachable from u ∈ S — contradicting v ∈ T.

Therefore: flow across the cut = (sum of capacities of outgoing edges) − 0 = c(S, T). Since flow across the cut = |f|, we have |f| = c(S, T). Combined with the upper bound, this means the current flow is maximum and this cut is a minimum cut.

Corollary — Correctness of Ford-Fulkerson
Ford-Fulkerson terminates when no augmenting path exists. Since each augmentation increases flow by at least 1 (integer capacities) and the maximum flow is finite, termination is guaranteed. At termination, the cut (S = {v : v reachable from s in Gf}, T = V \ S) has capacity equal to the current flow value — proving the flow is maximum by the min-cut max-flow theorem.

Finding the Minimum Cut from the Max Flow

The proof directly provides an algorithm for finding the minimum cut:

  1. Run Ford-Fulkerson (or any max-flow algorithm) to completion.
  2. In the final residual graph Gf, perform a BFS/DFS from s.
  3. Let S = all vertices reachable from s in the residual graph.
  4. Let T = V \ S.
  5. The minimum cut edges are all edges (u, v) in the original graph such that u ∈ S and v ∈ T.
Intuition — Why This Works
Every edge from S to T in the original graph is saturated (otherwise v would be in S). Every edge from T to S carries zero flow (otherwise u would be reachable via a backward edge). So the bottleneck of the network is precisely these saturated S-to-T edges — removing them disconnects s from t at the minimum possible cost equal to the max flow value.

Worked Example

Network from the course notes (Figure 9.6): s → a (cap 3), s → b (cap 6), a → c (cap 3), a → t (cap 4), b → d (cap 6), c → t (cap 4), d → t (cap 5). Max flow = 8.

9.3 Bipartite Matching

Bipartite matching is a canonical example of reducing a combinatorial problem to max flow. It demonstrates the real power of network flow: solving problems that seem unrelated to physical flow by encoding them as a flow network.

Definition — Bipartite Graph
A graph B = (V, E) is bipartite if the vertices can be split into two disjoint subsets L and R (the "left" and "right" sides) such that every edge in E connects a vertex in L to a vertex in R. There are no edges within L or within R.
Definition — Matching
A matching M ⊆ E is a subset of edges such that no vertex is incident to more than one edge in M. A maximum matching is a matching with the largest possible number of edges.

Motivating Example

Let L = {1, 2, 3, 4, 5} be job applicants and R = {6, 7, 8, 9} be available positions. An edge (u, v) exists if applicant u is qualified for job v. We want to assign as many applicants to jobs as possible such that:

  • Each applicant gets at most one job.
  • Each job goes to at most one applicant.

This is exactly the maximum bipartite matching problem. For the example in Figure 9.9 of the course notes, the maximum matching has size 3.

Reduction to Max Flow

The key insight is: one unit of flow = one match. We construct a flow network from the bipartite graph as follows:

Construction — Bipartite Graph to Flow Network
Given bipartite graph B = (L ∪ R, E):
  1. Add a super-source s with edges s → u for every u ∈ L, each with capacity 1.
  2. Add a super-sink t with edges v → t for every v ∈ R, each with capacity 1.
  3. Direct all original edges from L to R (i.e., u → v for each (u, v) ∈ E), each with capacity 1.
  4. Find a maximum flow in this network.
  5. The matched pairs are the edges u → v (u ∈ L, v ∈ R) that carry a flow of 1.

Why Unit Capacities Encode the Matching Constraints

  • Capacity 1 on s → u edges: At most 1 unit of flow can enter each left vertex from the source. Since all edges from u to R together carry at most 1 unit, at most one job is assigned to each applicant.
  • Capacity 1 on v → t edges: At most 1 unit of flow can leave each right vertex. Since flow is integer-valued (Ford-Fulkerson on integer capacities), each job gets at most one applicant.
  • Integer flow guarantee: Ford-Fulkerson always produces integer flows when capacities are integers. With unit capacities, every flow value is 0 or 1 — exactly encoding "matched" or "unmatched".

Full Algorithm

Algorithm — Maximum Bipartite Matching via Max Flow O(|V| × |E|) 
function MAX_BIPARTITE_MATCHING(B = (L ∪ R, E)):
    // Step 1: Construct flow network
    Create new vertices s (super-source) and t (super-sink)
    For each u ∈ L: add edge (s → u) with capacity 1
    For each (u, v) ∈ E: add directed edge (u → v) with capacity 1
    For each v ∈ R: add edge (v → t) with capacity 1

    // Step 2: Find maximum flow
    flow = MAX_FLOW(G, s, t)   // Use Ford-Fulkerson

    // Step 3: Extract matching
    matching = {}
    For each edge (u → v) with u ∈ L, v ∈ R:
        if f(u → v) == 1:
            matching.add((u, v))

    return matching  // |matching| == flow

Worked Example

Applicants L = {1, 2, 3, 4, 5}, Jobs R = {6, 7, 8, 9}. Edges: 1-6, 1-7, 2-7, 3-7, 3-8, 4-8, 4-9.

Flow network construction:

  • s → 1, s → 2, s → 3, s → 4, s → 5 (all capacity 1)
  • 1 → 6, 1 → 7, 2 → 7, 3 → 7, 3 → 8, 4 → 8, 4 → 9 (all capacity 1)
  • 6 → t, 7 → t, 8 → t, 9 → t (all capacity 1)

Ford-Fulkerson finds max flow = 3. One valid maximum matching (saturated L → R edges): {(1, 6), (3, 7), (4, 8)} or similar — matching 3 applicants to 3 jobs. Applicant 2 (only wants job 7, which is taken) and applicant 5 (no edges) are unmatched.

Time Complexity

Complexity — Bipartite Matching via Ford-Fulkerson
O(|V| × |E|)

Argument:
  • The maximum flow value is at most min(|L|, |R|) ≤ |V| (bounded by the smaller side of the bipartition).
  • Each DFS augmentation takes O(|E|).
  • Therefore total complexity: O(|V| × |E|).

Alternating Paths Perspective

When Ford-Fulkerson is applied to the bipartite matching flow network, the augmenting paths it finds have a specific structure: they strictly alternate between forward edges (unmatched L-to-R edges being added to the matching) and backward edges (matched L-to-R edges being un-matched to redirect flow). This is why the technique is also called the alternating paths algorithm for bipartite matching.

In practice, the flow network does not need to be constructed explicitly — one can implement the matching algorithm directly by performing DFS/BFS that alternates between unmatched and matched vertices, maintaining only the current matching state.

The Hopcroft-Karp Algorithm

A faster algorithm called Hopcroft-Karp solves the maximum bipartite matching problem in O(√|V| × |E|) time. It uses the same flow network but employs a more efficient maximum flow algorithm that finds multiple augmenting paths simultaneously in a BFS layered graph, achieving the improved bound.

König's Theorem

Theorem — König's Theorem
In a bipartite graph, the size of the maximum matching equals the size of the minimum vertex cover (the smallest set of vertices that "covers" every edge — i.e., every edge has at least one endpoint in the set).

This is a direct consequence of the min-cut max-flow theorem applied to the bipartite matching flow network: the min-cut in the flow network corresponds exactly to a minimum vertex cover in the original bipartite graph.

Big Picture — Why Network Flow is So Powerful
Network flow algorithms are not just for routing problems. The max-flow / min-cut framework can be applied to any problem where:
  • You need to maximise a flow-like quantity subject to capacity constraints.
  • You need to find the "bottleneck" or "cheapest cut" in a system.
  • You can encode mutual exclusivity or limits using unit-capacity edges.
The reduction from bipartite matching is the first of many such reductions (circulations with demands, project selection, etc.) that demonstrate this versatility.

The Three Equivalent Conditions for Max Flow
The following three statements are equivalent for a flow f in network G:
  1. f is a maximum flow.
  2. There is no augmenting path from s to t in the residual graph Gf.
  3. There exists an s-t cut (S, T) such that |f| = c(S, T).
This equivalence is precisely the min-cut max-flow theorem, and it proves both the correctness of Ford-Fulkerson and the method for finding the minimum cut.
